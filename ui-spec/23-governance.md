# 23 · 治理：版本、变更流程、验收定义、视觉基线

这套规格是长期使用的「UI 宪法」，不是一次性文档。以下规则保证半年后加功能时它仍然有效。

## 1. 版本与冻结

- 规格版本号跟随原型：`v3.0.3` 起。文档改动 → 修订号 +1（3.0.4）；组件或模板增删 → 次版本 +1（3.1）；token 或版式变更 → 主版本 +1（4.0）。
- **冻结层**（改动需产品负责人书面确认，且升主版本）：`tokens.css` 颜色与字号、窗口版式（03 §1–§3）、五个页面模板、六个 tone 语义、品牌 Logo 用法。
- **受控层**（改动需同时更新原型 + 对应 md + golden 截图）：组件清单（02 / 20）、页面结构（04）、状态词表与错误映射（22）、文案词表（06）。
- **自由层**（PR 内自行更新）：具体页面内容、示例数据、预览截图。

## 2. 变更流程

```
提出 → 原型模块改动（work/modules/）→ 重建 HTML → 截图 → 改 md → PR「spec:」前缀
     → 产品负责人看截图确认 → 合并 → CHANGELOG.md 记一行 → 代码 PR 引用该 spec PR
```
- 代码 PR 不得包含规格未覆盖的 UI；发现规格缺口，先发 `spec:` PR。
- 一个 `spec:` PR 只改一件事。
- `CHANGELOG.md` 格式：`日期 · 版本 · 层级（冻结/受控/自由）· 改了什么 · 为什么 · 影响的页面`。

## 3. 一个 UI 改动的「完成定义」（Definition of Done）

- [ ] 原型里能点到，截图已进 `prototype/previews/`
- [ ] 对应 md 已更新（04 / 02 / 05 / 06 / 22 至少其一）
- [ ] 只用了现有组件与 token；`no-hardcoded-color` lint 通过
- [ ] 暗 / 亮两主题、Win / Mac 两平台截图各一（Linux 二期后加）
- [ ] 空态、加载态、至少一个失败态
- [ ] 键盘可完成全部操作；焦点环可见；Esc 行为正确
- [ ] 文案过 06 检查（动词按钮、状态词表、无禁用词）
- [ ] 保留 / 新增 `data-testid`；e2e 通过
- [ ] golden 截图基线更新并经审阅
- [ ] CHANGELOG 记录

## 4. PR 模板（`.github/PULL_REQUEST_TEMPLATE.md`）

```
## 做了什么
（一句话）

## 规格依据
- spec PR / 章节：
- 原型模块：work/modules/xx

## 截图矩阵
| 状态 | 原型 | 实现（暗） | 实现（亮） |
|---|---|---|---|

## 与原型的差异
（无 / 列出并说明是否有意为之）

## 待决策
（无 / 列出）

## DoD 自检
- [ ] …（复制 23 §3）
```

## 5. 视觉回归基线

- 基线目录 `tests/visual/golden/<page>/<state>-<theme>-<os>.png`，由 Playwright 在 1280×820、zoom 1.0 下生成。
- 每个页面至少四张：默认、空态、失败态、暗色；账号相关页面加「余额红」态。
- CI 对比阈值 0.2%；超出即失败，需要在 PR 里附「更新基线」的截图对照并由审阅人确认。
- 基线只能由带 `spec:` 依据的 PR 更新。

## 6. 角色

| 角色 | 能做 | 不能做 |
|---|---|---|
| 产品负责人 | 确认 spec PR、拍板冻结层变更、按截图验收 | — |
| AI 实施代理（Codex 等） | 改自由层与受控层（附原型 + 截图）、写代码 | 改冻结层；跳过原型直接写 UI；自创样式 / 文案 |
| 审阅代理（另一 AI 或人） | 对照 DoD 打回 | — |

## 7. 例行维护

- 每次发版：核对 `22` 注册表与代码常量一致（脚本 `scripts/check-registry.ts`）。
- 每季度：跑一遍全部 golden，清理无引用的组件 story 和废弃截图。
- 品牌套装升级：只替换 `assets/brand/` 文件，不改引用；升级后跑 07 的 Logo 位置清单。
