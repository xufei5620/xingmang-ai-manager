# 星芒 UI v4.0

**状态：现行界面基线。** 2026-10-14 产品负责人（yoyo）确认：把这一版改版原型定为正式规范，开发照它改界面。
它取代 v3.1.1 的视觉和页面结构；v3.1.1 阶段在 `src/renderer-v2/` 里已经接好的业务（IPC、账号、充值、安装、Key、聊天、画布）照用，不重写。

## 以什么为准

从上到下，前面的说了算：

1. 产品负责人的明确决定，见下面「已拍板的决定」。
2. 代码和后台里的真实业务：金额、订单、账号能力、连接线路、报错文案以代码为准，原型里的数字只是示例。现有能力原型漏画了的，不能删。
3. [星芒AI管理工具-v4原型.html](星芒AI管理工具-v4原型.html)：视觉、页面结构、交互和文案。检阅条「视图」切到「组件规范」，就是 v4 的颜色令牌、字号、圆角、间距和组件清单。
4. `ui-spec/01–24` 号文档（v3.1.1）：v4 没改到的地方继续有效；和原型冲突时以原型为准。改到哪一块，就把对应的 md 一起改掉。

## 怎么看

用浏览器直接打开原型文件。单文件，离线能用；字体从 Google Fonts 取，断网时退回系统字体。

窗口上方的检阅条可以切换：视图（界面 / 组件规范）、配色、系统（Windows / macOS）、窗口尺寸、账号情况、账号来源（星芒账号 / 历史账号）、工具状态、网络。
检阅条，以及界面里写着「原型」的灰色小按钮（填入示例、模拟支付结果、示例数据说明），都只是原型用的，不进产品。

## 已拍板的决定

- 配色只留两套：黑金深色、晨曦金浅色。
- 正文 14px。
- 金色只用在主按钮、选中、焦点和金额上；浅金按钮只给充值、购买和需要注意的事。
- 说明文字能省就省。
- 首页的工具按厂商排成卡片，不做筛选和搜索。
- 每个工具的配置弹窗只管这一个工具；Codex CLI 和 Codex 桌面端共用一份配置。
- 设置左侧的分组名一律四个字。
- 「退出登录」「切换账号」放在个人中心的账号概览里。
- 不支持 Gemini CLI。
- 画布不在这次改版范围内。
- 工具和支付渠道前面的字母方块是占位，正式版按 [07](../07-icons-brand.md) 换成品牌图标。
- 960 × 560 最小窗口时，界面缩放最低到 90%（[03](../03-layout-window.md) §1 已改）。
- 充值档位、赠送、价格、最低额和支付渠道都从当前账号的站点读，界面不写死。两个站现在都是 1 元到账 1 美元；原型里的档位、最低额和渠道是示例。
- 付款在星芒自己的支付窗口里完成，到账、超时、失败由星芒去查，不让客户回来点「我付好了」；订单不能取消，也没有「继续支付」（站点没有这两样）。
- 历史账号（另一个站点，老用户的账号）的登录入口、找回密码、能力差异和两组连接线路，照现在代码里的实际行为画：`features/auth/AuthFlow.tsx`、`pages-account.tsx`、`registry/connection-routes.ts`。

### 版式与令牌

- 内容区最宽 1000、在侧栏右侧居中，侧栏收窄条和导航行变矮两个断点，照 [03](../03-layout-window.md) 不变；缩放下限改成 0.9（最终倍率下限 0.85）。代码里现在只有一个下限 `UI_MIN_ZOOM = 0.7`（`electron/window-preferences.ts` 的 `calculateUiZoom`），实施时要拆成这两个。
- 外壳尺寸以原型为准：标题栏并进顶栏，顶栏 44 高，窗口按钮在顶栏右端（macOS 的红黄绿在侧栏顶上）；侧栏 224 / 60；状态栏 28；导航行 34，窗口矮时 30。03 §2 的表在实施外壳那一步跟着改。
- 两套配色的令牌值以原型「组件规范」为准。`ui-spec/tokens.css` 被 `src/renderer-v2/styles/tokens.css` 直接引用，换它就是换界面，所以留到实施 PR 里和组件一起换；雾青、极光紫两套皮肤到时一起去掉。

## 实施要点

- 还是在 `src/renderer-v2/` 里改，不另起新的一棵树。先改 registry（`pages.ts`、`business.ts` 里的 `accountTabs`、`settingsGroups`、`settingsItems`），页面只读 registry。
- 现有 `data-testid` 全部保留。搬了家的入口（游戏加速、备份、更新、安装卸载、我的订单、登录设备），顶部搜索和命令面板要能找到新位置。
- 每改完一块：暗、亮两套截图对照原型，改对应的 md，在 [CHANGELOG](../CHANGELOG.md) 记一行。
- 原型的检阅条、「原型」灰按钮、示例数据都不进产品。

建议的顺序（可以调）：

1. 令牌、两套配色、字号、缩放下限。
2. 外壳和侧栏：导航调整、账号卡、充值入口。
3. 首页：工具按厂商排成卡片。
4. 个人中心六个页签。
5. 设置八组：并进游戏加速、备份、更新。
6. 精选、外接工具、技能、插件、记录、教程、检查、反馈与客服、聊天。

## 动手前要先定的事

做到对应那一块之前，要先回去问产品负责人：

- 「异步任务」放在哪：原型没画。
- 「安装卸载」页里 Node.js 和 Python 的安装、卸载、修复和安装日志放在哪：原型里只有工具卡片上的安装、卸载，和检查页里的状态。
- 账号安全页的两步验证开关和备用码：现行代码只有登录时输验证码那一步，后台支不支持要先核实；不支持就先不放这一行。
- 精选里的创作者市场（上传作品、出售所得进余额）：后台还没有。在后台做好之前，「创作者作品」「我的作品」两个页签和「上传作品」先不上。
