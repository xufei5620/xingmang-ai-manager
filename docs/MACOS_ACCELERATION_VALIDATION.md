## 浏览器测试原有问题

全套重现了此前 0.2.2 本地验证遇到的三个问题，本轮没有修改 renderer 或这三个源测试：

1. 密钥分组：Mac 的 Escape 关闭父对话框，导致等待选项超时。诊断副本使用确认原选择来关闭原生下拉框，其余断言保留后通过。
2. 聊天复制：`.last()` 在助手内容渲染前可能选到用户消息。诊断副本固定选择助手消息的复制按钮，原有内容断言通过。
3. 隐藏聊天：调用 React 状态设置后立即计数可能早于提交。诊断副本等待隐藏/显示状态再检查弹层及草稿，原有断言通过。

诊断副本仅保存在忽略目录，不把全套结果描述为全绿，也没有为通过测试而改变产品行为。

## 2026-09-14 连接失败回归

用户点击开始后未出现授权窗口。macOS authd 记录原生组件无法创建 code ref（100001）。同一份只读 AuthorizationCreate 探针在 `/private/tmp` 返回 0，在 Desktop 项目目录返回 -60008，定位为授权服务无法读取受保护目录下的程序身份。

修复包括：

- 组件先在用户 Application Support 下建立独立私有运行副本，复制后核对 SHA-256，再以 0500 权限执行；不覆盖存活进程文件，旧的中断副本也不会阻塞启动。
- 请求 SCHelper 实际使用的 `system.services.systemconfiguration.network` 权限，而非仅用于网络偏好面板的 `system.preferences.network`。
- 等待 configd 异步发布 Setup 状态（单调时钟，最多 2 秒），避免 Apply 返回后立即读到旧值而误判失败。
- 后端仅对固定内部授权错误码给出明确中文说明，原始错误和私有路径不返回界面。

验证：41 项针对性 TS 测试、17 项原生测试和类型检查通过；完整 `npm test` 为 4121 项通过、50 项跳过，脚本/UI 测试通过。用户确认系统授权后，真实 Mihomo SG 线路（本次 322 ms）启动、系统代理启用、停止恢复均通过；`scutil --proxy` 与测试前一致，内核退出、恢复记录已清除。首次短测试因 20 秒等待上限短于人工授权耗时而超时，最终验证采用 180 秒上限并完整通过。未改系统授权数据库或扩大系统信任。
