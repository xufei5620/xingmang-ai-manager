## 用户

- Windows 上 Codex 桌面端开着时点「更新」（或安装卸载页的「重新安装」），先问一句「Codex 桌面端还开着」再关它：
  点「关掉并更新」才关掉、更新，更新完星芒替你重新打开；点「先不更新」什么都不动。它没开着时照旧直接更新。

## 开发

- 第三十二批 C：`src/renderer-v2/App.tsx` 的 `install()` 在 Windows 上更新已装的 Codex 桌面端之前，先现问一次
  `getCodexDesktopStatus`（问不出来按最近一次检测），开着就弹「Codex 桌面端还开着」确认框。主进程三条安装路线
  （商店、官网离线包、国内镜像）动手之前都会先关掉它，5 秒没关掉就强行结束，以前不问就打断正在进行的回答。
  客户点了「关掉并更新」，这一趟结束时（装成、没换包、没装成、中途取消都算）它关着就照「打开」那条路重新打开：
  商店那一路是先关再装，商店没装上、国内线路又没有更新的版本时结果是「没换包」，它却已经被关了；还开着就什么都不做，
  也不问「要不要重启」。点「先不更新」安装结果是新的 `declined`，安装卸载页不再说「这个工具正在安装」；现问那一会儿
  首页「更新」转圈，安装卸载页这时点「取消」就是不装了。判断逻辑在 `features/tools/codex-desktop-update.ts`。
