# 发现与修复目标

状态范围见 [基线说明](README.md#基线与增量边界)。本页包含 4 项旧问题的部分修复、7 项新增确认及 3 条历史专项缺口；不是把同一个残余重复算成新问题。非安全源码链接固定在已审查提交，安全细节不公开。

## 四项部分修复

<a id="partial-o05"></a>
### O05：分镜解析仍少算一次可能的付费请求

**已修部分：** 分镜解析已经计入付费步骤，不再按纯本地操作展示。**残余：** 确认框预告最多一次；模型首次返回格式不合格后，自动纠错会再调用一次。

本轮用真实预检与执行模块做离线对照：正常输出预告 1 次、实际 1 次；格式纠错预告仍为 1 次、实际 2 次并成功。这里统计的是模拟远程请求次数，没有据此推断服务端实际扣款。对应 [预检上限](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/canvas-v2/src/runtime/run-preflight.ts#L340) 和 [纠错调用](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/electron/canvas-node-executors.ts#L318)。

**修复目标：** 披露包含纠错的请求上限，或第二次请求前再次确认。**验收：** 正常一次、格式纠错两次分别核对预告和实际次数；网络错误和超时不能未经确认自动重发；取消后不发第二次。

<a id="partial-o06"></a>
### O06：选中的历史图片仍可能被另一张缓存图替代

**已修部分：** 来源历史仍在时，选择图片 A 后下游确实使用 A。**残余：** 来源记录被近期历史淘汰后，下游仍可能无提示改用缓存图片 B。

本轮通过真实运行服务产生足够的新历史触发淘汰；正常组使用 A，淘汰组实际使用 B，而不是重新生成图片。问题是选择与输入不一致。对应 [采用来源查找](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/electron/canvas-run-store.ts#L423) 与 [缓存和下游输入处理](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/electron/canvas-run-engine.ts#L660)。

**修复目标：** 当前项目采用的素材证明不能依赖会淘汰的短期历史。无法确认 A 时明确报错或要求重新选择，不能静默换成 B。**验收：** 历史淘汰、重开、历史读取失败后三种场景，都必须使用 A 或明确停止；正常选择和输入修改后的缓存校验继续有效。

<a id="partial-n2"></a>
### N2：视频提交记录写入失败后，重开仍可能丢失额外付费提醒

**已修部分：** 正常收到“提交结果不明确”时，会保存请求状态；重开仍保留提醒，再次生成要求确认。**残余：** 提交前的状态记录写入失败仍继续提交，如果在收到结果前退出，恢复时可能被当作没有提交过。

本轮在真实任务存储和服务中隔离模拟磁盘写入失败，确认请求仍交出；新服务恢复为空，原页面随后清除不确定状态。再次操作仍有普通费用确认，但缺少“上一单可能已经扣费”的额外提醒。没有真实生成或扣费。对应 [提交前持久化](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/electron/ai-video-service.ts#L735) 和 [页面恢复状态](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/src/renderer-v2/features/video-studio/useVideoStudio.ts#L284)。

**修复目标：** 提交前的状态必须可靠保存，保存失败则停止提交；恢复时不能把“记录丢失”和“确定未提交”等同。**验收：** 模拟磁盘满、请求已交出后退出、重新打开，上一单不确定状态仍可识别；再次生成必须披露重复付费可能；正常恢复和明确未提交的取消不受影响。

<a id="partial-d06"></a>
### D06：新版入口已拦截，旧工程仍可能静默少用输入

**已修部分：** 当前宿主不支持的“全部输入”会明确阻止执行。**残余：** 旧工程的同类设置在转换时丢失语义，仍可能按只取第一张图成功运行。

本轮核对真实工程转换与执行链：新版配置在预检被拒；旧工程的两个输入只传入第一个。工程转换使用源码提取的真实函数，不是浏览器点击验证。对应 [旧设置读取](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/canvas-v2/src/lib/router-strategy-contract.ts#L29) 和 [请求转换](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/canvas-v2/src/App.tsx#L428)。

**修复目标：** 旧格式迁移成受当前能力检查的明确语义，或要求用户重新选择；不能删除原意后继续运行。**验收：** 导入及重开旧工程时不得静默退化为只用第一项；新旧工程相同意图得到一致结果或一致拒绝；原本只选第一项的工程继续正常。

## 七项新增确认

以下均有当前业务模块的离线反例和正常对照。“新增发现”不代表本轮提交引入，也不表示已在生产发生。建议优先级均为 P2；安全条目的排期由维护者按受控材料确定。

<a id="r29-01"></a>
### R29-01：监听恢复后可能漏掉刚发生的 Codex 错误

首次使用或日志监听恢复时，已写完且不再变化的新日志可能未被发现，用户停在报错处却等不到处理。真实监听模块与临时文件的离线对照确认：恢复后漏检，追加新写入后能够识别。对应 [监听恢复逻辑](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/electron/codex-payload-limit.ts#L277)。

**修复与验收：** 首次监听和恢复时有界补查近期文件，限制时间、数量和字节量。目录晚出现、错误已写完且没有后续写入时仍须处理一次；过时日志忽略，重复事件不重复提醒，也不能无限扫描全部历史。

<a id="r29-02"></a>
### R29-02：同一会话切线后再次报错，被去重逻辑吞掉

同一会话先在线路 1 报错并切到线路 2，随后再报相同错误时，本应升级到“新开对话”的提示，却被之前的已处理标记挡住。真实服务对照中，同会话第二阶段不提示，另一个会话的相同错误可提示。对应 [错误去重与处理阶段](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/electron/codex-payload-limit.ts#L401)。

**修复与验收：** 区分线路、处理阶段和重试状态。同阶段重复事件限频；同会话切线后的新错误须升级提示一次；临时探测失败恢复后可重试；重开后既保留必要去重，也不能永久屏蔽新的阶段。

<a id="r29-03"></a>
### R29-03：切账号或换官方来源后，旧错误处理仍可能迟到生效

探测等待期间改变账号或工具来源，旧结果仍可能执行不属于当前状态的线路处理或显示提示。本轮确认了迟到动作和提示；未证明跨账号使用密钥、错误扣费或覆盖官方配置。对应 [异步错误处理](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/electron/codex-payload-limit.ts#L419)。

**修复与验收：** 账号、来源和请求代次校验覆盖探测、改变线路、跟随及提示全过程。等待期间切账号、退出、切官方来源，旧结果均不能影响新上下文；当前有效请求仍能正常处理。

<a id="r29-04"></a>
### R29-04：补发另一平台时，分批发布限制可能失效

同版本已经对 Windows 分批发布，随后补发 Mac 并继续选择部分放量，新增平台可能没有进入受控范围，实际不受该比例限制。离线调用真实发布计划及客户端规则确认此结果，没有发布任何版本。对应 [发布计划](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/scripts/release-rollout.cjs#L143)。

**修复与验收：** 新增平台纳入同版本受控范围，保留已有暂停和比例含义。分别覆盖部分放量、暂停后补平台、同平台重跑和全平台发布；补发不能解除已有控制。

<a id="r29-05"></a>
### R29-05：某个平台全部升级失败，健康统计仍可能建议扩大发布

统计平台集合只取已在新版出现的记录，某平台没有任何成功升级时可能没有独立统计行，失败被其他平台的成功样本稀释。本轮使用合成记录确认误判，不涉及客户数据。对应 [健康统计的平台集合](https://github.com/xufei5620/xingmang-ai-manager/blob/b246f99b914d13ed1d48386be34c8224b6229caf/scripts/rollout-health.cjs#L132)。

**修复与验收：** 纳入有失败记录的平台及当前受控平台，分别计算结果和证据量。某平台只有失败时必须显示并停止；证据不足只能等待，不能由另一平台的成功替代；正常全平台统计保持有效。

<a id="r29-06"></a>
### R29-06：手机遥控开通与后台停用的状态可能不一致

功能仍在开通检查时收到后台停用状态，较晚完成的开通仍可能继续接受任务。本轮离线验证确认该功能状态问题，不公开具体入口和调用时序，不涉及给真实用户发消息或执行真实任务。

**修复与验收：** 停用应对所有正在进行的开通生效。覆盖开通前、等待期间和开通后的停用；停用后不能继续接受或执行任务，正常启用和恢复仍可用。此项与已修 N1 的旧触发链不同，不能用 N1 通过代替此项验收。

<a id="r29-07"></a>
### R29-07：敏感剪贴板内容的自动清理仍有可靠性缺口

已确认存在需要修复的清理责任问题。只公开抽象影响及验收目标，详见 [安全摘要](security-status.md)；触发细节、源码位置和隔离材料不进入公开 PR。
