# 历史账号视频路由与计费边界

对应历史台账 H-VIDEO-*，不能从原17/后续编号表中漏掉这一整份专项。用户所说 sub2spi 按项目的 sub2api 历史账号理解。

## 客户端结论

**已核对的正常产品路径中，历史账号被禁止生成视频，没有发现客户端自动借用 xm 账号/Key 或跨到 xm 视频入口的逻辑。** 这与“线上后端绝不会漏记账”是两回事。

历史专项在 `ffc04922` 通过真实工厂、账号适配器和凭据协调器的隔离模拟验证：主窗口和画布两份服务的 generate/resume 均拒绝历史账号，4次调用、生成HTTP请求0；账号域隔离、同域双线路、任务归属及签名下载另有7组对照。132个相关测试当时通过。它们是旧执行证据，本轮通过相关文件哈希及调用边界复核后复用，不计成本轮新跑132项。

| 疑问 | 当前可以说什么 |
|---|---|
| 历史账号可否从视频页正常提交 | 页面和主进程服务均有历史账号限制；主进程保护不依赖按钮隐藏 |
| 历史线路失败是否借用xm | 历史站只在自身primary/direct之间切换；账号域的凭据与任务目录分开 |
| 成品视频来自第三方地址是否等于串站生成 | 成品可能是签名CDN下载；下载不附API Key，与生成请求的账号归属不同 |
| “写分镜”是否免费视频 | 它是文字模型调用；底层文字能力若被调用仍走当前账号计费链，不能视为免费视频 |
| quota=0 是否代表免费 | 此处表示不另设Key额度上限，不代表模型价格为0 |

对应代码入口：`electron/bootstrap/ai-services.ts`、`electron/relay-sites.ts`、`electron/site-runtime.ts`、`electron/realm-data-roots.ts`、`src/renderer-v2/pages-business.tsx` 和 `features/video-studio/VideoStudioPage.tsx`。最新视频停止逻辑的增量不改变账号后端隔离，见 [增量复核](latest-delta.md)。

## 后端结论只能保留为待验证风险

此前额外检查的是另一仓库 sub2api **2026-09-19 的本地提交 `1a9d49e16f7a22c432b428fce4af8d731f1fa364`**，不是本次线上部署证明。该版本 Grok 视频链有“先返回完成状态、随后结算”的设计，异常下可能依赖后续查询重试；持久化兜底结算的完整性仍需验证。详细异常触发和源码定位留在受控材料，不在公开PR发布可利用步骤。

修复目标：任务的计费事实持久化，完成与结算状态分开；重试幂等，服务恢复后可补偿；定期对账未结算任务并告警。验收应在隔离后端模拟存储、锁、记账故障和进程重启，证明成功产出最终结算一次、失败任务不多扣、重复查询不重复扣。**不能仅靠界面余额变化作为验收。**

以下几种情况不是同一个“免费漏洞”：任务尚未完成结算、消耗的是订阅额度、客户端余额缓存未刷新、管理员明确配置为免费。当前线上是否存在这些配置，本次未读取或推断。

历史账号的服务端若被管理员配置为向 xm 转发，那是后端运营账号链路；客户端路由保护不能证明服务端上游一定不是 xm。用户账与运营者上游账也是两笔独立账。实际配置尚未核实。

## 后续需要的证据与验收

要判定某笔视频是否漏扣，需对应的后端部署版本、任务与计费记录、余额/订阅流水及当时生效价格；应先只读对账，不在生产故障注入或反复生成来试漏费。该旧后端风险不计入本仓已确认缺陷数，不声称当前线上受影响。

客户端后续改动须持续保留：历史账号主进程拒绝、跨站同编号隔离、只在同域切线、恢复任务归属检查、下载不转发Key。测试仍全部mock，真实生成/付费验证需明确任务范围。
