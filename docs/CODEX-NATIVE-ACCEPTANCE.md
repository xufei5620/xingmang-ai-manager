# Codex 原生客户端接入验收

本表记录**真实客户端与星芒中转**的验收证据。#618 的本地 mock 只验证本软件构造和解析协议的逻辑，不代表线上中转、原生客户端或官方账号权益已经通过。所有项目当前均为**待真实验收**。

## 环境与版本矩阵

| 维度 | 验收时记录 | 当前证据 |
|---|---|---|
| ChatGPT/Codex 桌面版本 | 应用显示的版本、Windows AppX 包版本或 macOS 应用版本、安装来源 | 待真实验收 |
| 桌面内置 runtime | 原生应用实际使用的 runtime 与版本；不要用独立 CLI 的版本替代 | 待真实验收 |
| Codex CLI | 独立 CLI 的版本、是否与桌面共用配置和登录来源 | 待真实验收 |
| 插件与扩展 | 名称、版本、安装来源、桌面内是否加载及权限提示 | 待真实验收 |
| 模型 | 配置中的模型 ID、原生应用实际请求的模型 ID、可用分组 | 待真实验收 |
| 中转 | 当前站点、协议入口、请求状态、用量记录；密钥只记掩码 | 待真实验收 |

## #618 本地检查的边界

普通「连接自检」中，Codex 的 `GET /v1/models` 仅证明当前密钥可取得模型清单且所选模型在清单内。用户在「Codex 工具调用检查」中另行确认可能计费后，才发送**最多两次**有输出上限的 JSON 请求：第一轮要求固定无副作用函数调用，第二轮把随机标记作为该调用的工具结果回传，并严格核对回答。模型给出的命令、文件路径或其他工具调用均不执行。

成功结论只覆盖**星芒中转的非流式 Responses JSON 与虚拟工具结果回传**。它不覆盖项目级覆盖配置、原生应用进程实际发出的请求、WebSocket/SSE 流式事件、取消、搜索、生图、电脑操作、插件调用或官方 ChatGPT 账号权益。失败也不能单凭一次 JSON 探测断言原生桌面完全不可用。工具调用和 `function_call_output.call_id` 的协议形状依据 [OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)；流式完成与错误需按 [OpenAI Streaming API responses](https://developers.openai.com/api/docs/guides/streaming-responses) 另验。

## 给下一位测试员的步骤

1. 使用独立的测试账号、限额密钥和测试工作目录；记录上表版本、模型及中转站点，保存配置备份。不得把完整 Key、聊天内容或无关用户文件写入验收记录。
2. 在「检查」页先运行基础连接自检，记录「模型清单可见」或具体失败层。若预算允许，阅读计费说明并单独确认一次 JSON 工具往返；记录状态、HTTP 码和中转用量。不要把本地 mock 测试写成线上结果。
3. 从**原生桌面应用**打开测试工作目录，逐项执行任务矩阵。每项记录时间、应用版本、所选模型、可复核的截图或脱敏日志、预期与实际、是否计费。流式应分别记录增量、完成、错误和取消，而不把连接关闭当成功。
4. 任一项失败时，先停止继续测试，记录可复现步骤与脱敏错误；区分账号权限、模型分组、中转协议和原生应用行为。不要通过放宽工具权限或改写生产配置掩盖失败。
5. 验收后恢复原配置与账号来源，关闭测试会话，只清理本次创建的测试目录，检查备份仍可用，并核对测试账号用量。未通过的项目维持「待验收」或明确记为「失败」，不要推断其他项目结果。
