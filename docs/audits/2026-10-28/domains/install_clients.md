## 当前仍存在的问题与实施验收

### N1 · 关闭手机遥控后，启动中的任务仍会迟到执行（P1）

- **条件/影响**：手机任务正等待 `spawnCodex` 或 app-server 初始化时关闭渠道；界面已是关闭/空闲，之后仍发送任务，且服务重新持有未停止的子进程。未证明真实计费或文件修改。
- **当前位置**：`electron/codex-remote-service.ts:712–731` 关闭渠道；`1028–1047` 等启动后不核对 turn/channel 是否仍有效；`1084` 迟到启动重新写入 `this.codex`；`1098–1102` 停止仅处理已经赋值的实例。
- **fresh 证据**：`install_clients-remote-result.json` 的 `disabledDuringSpawn`：关闭返回后 `turn/start=1`、`kill=0`、`serviceStillOwnsRunningProcess=true`。它运行当前原服务，仅进程/渠道为替身。
- **修复方案**：将启动尝试绑定生命周期代号；关闭、dispose、切换工作区后使旧启动失效。迟到实例必须停止且不能发布为当前实例；`ensureCodex`、`thread/start` 返回后再次核对同一 turn/channel 仍有效，失效请求不得发送 `turn/start`。不要让后开的合法渠道复用旧失效启动。
- **验收**：分别在 spawn、initialize、thread/start 等待点关闭/退出，完成迟到响应后没有新 turn、没有残留进程；重开渠道后能正常启动一次；只关闭一条渠道时，不误杀另一条正在执行的有效任务。

### N8 · 中文在进程管道分块时会乱码（P2）

- **条件/影响**：stdout 的两个 Buffer 把一个 UTF-8 汉字分开；答复或审批路径变为替代字符，JSON 仍被成功处理。
- **当前位置**：`electron/codex-remote-app-server.ts:184–186` 对每块独立转 UTF-8；`codex-remote-process.ts:80–88` 没有设置流式 decoder。
- **fresh 证据**：同一新结果文件 `utf8AcrossPipeChunks`，`中文路径：测试完成` 变为 `���文路径：测试完成`，有效 JSON 仍分发。原单测只切 ASCII 字符串，没有切多字节 Buffer。
- **修复方案**：用 `StringDecoder` 或给 stdout 设置 UTF-8 流式解码；退出时冲刷 decoder，保留现有字节数和单行上限，避免把字符数当字节数。
- **验收**：中文与四字节字符在每个可能字节边界拆开均原样还原；ASCII、连续多行、非法尾字节、超限终止行为不回退。
