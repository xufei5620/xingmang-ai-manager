# 视频剪辑

把 AI 生成的几段片段拼成一条成片。第 1 期「一句话出片」分三步做：本目录的拼片引擎、主进程的分镜和出片段通道、视频工作台，三步都已接上。2026-11-20 起（聊天、画布、视频剪辑合成「创作」一页的第 1 步）工作台不再是侧栏单独一页：它在「创作」里点开一条视频时出现在右边，开哪一条、新建、改名、删除都归「创作」（`features/create/`）。

## 页面

`VideoStudioPage` 是一条视频的工作台，由「创作」页挂在右边（`features/create/CreatePage.tsx`，按视频编号 `key`，换一条就重新挂）。`registry/pages.ts` 里的 `video` 还在，但成了「创作」的别名：`navigate('video')`（引导里的「做图、做视频」、教程里的入口）落到「创作」，接着最近那一条，没有就新开一条。历史账号「创作」里不列视频、起始页也没有「做一条带字幕的短视频」那张卡（历史账号站没有视频模型）；视频剪辑临时停用时列表照列，点开是「视频剪辑暂时停用」。工作台自己没有页面标题、「新建一条」「重新开始」和草稿箱。

流程：写一句想法 → 「编写分镜」（文字模型拆成几个镜头，每个镜头一句画面描述和一句字幕）→ 改描述、字幕，上移、下移、删掉、加镜头，想让哪一镜从一张图开始动就「用一张图开头」或「AI 生成图片」 → 「生成全部 N 段」（先确认几段、每段几秒、按段计费；同时最多 3 段）→ 某段不满意单独「重新生成」，开头发呆、结尾走样就「开头剪掉」「结尾剪掉」几秒 → 想要背景音乐就「加配乐」，想要柔一点就「镜头之间」选「淡入淡出」、打开「结尾淡出」→ 「合成视频」（在这台电脑上拼，不花钱）→ 用播放器打开、另存，或「打开文件夹」到 AI 作品文件夹里找。

教程有一章 `video`（`registry/tutorials.ts`）照这个流程讲四步。页面改了按钮名、下拉名，`VideoStudioPage.test.tsx` 里核对教程的那条会红，教程跟着改。

- 每一笔要花钱的操作（生成、重新生成）都先弹确认；停下时说清哪几段已经交给服务端、照样扣费。
- 生成的确认框在「每段单独计费。」后面报「当前余额 $X。」（外壳那份余额，`useSharedAccountBalance`）；余额读不到、或者那份余额不是这个账号的，就不写这句，同充值页卡头（#1406 P2-1）。按型号报价还没做。
- 「停止生成」只停排着队的和还没交给服务端的。已经交出去的那几段钱已经扣了、停不下来：镜头上照旧是「生成中」，页面拿原来的请求号接着等（`resumeAiVideo`），好了挂回原来的镜头，不会变回「还没生成」让「生成剩下的」再付一次钱（#1406 P1-1）。主进程那边拿不到这一单（停在提交到一半）的，按主进程那句「提交结果不明确」算失败。在接回的这几单再点停止也不去碰它们。
- 一条视频一个文件（0.2.25 总单 #79，融合第 1 步）：工程（想法、设置、分镜、片段和成片的编号）连同客户起的名字、最后动它的时间，由主进程存在用户数据目录下按账号分开的文件夹里（`electron/video-studio-project-store.ts`，经 `video-studio:read-projects` / `video-studio:write-projects`），最多 200 条。文件里写什么、读回来怎么认在 `library.ts`（纯函数）；读写在 `useVideoStudioLibrary.ts`：改动攒 400 毫秒一批写，发出片段请求之前、页面藏起来、退出之前立刻写（请求号要先落盘，见下面「排队、进度不记」那条）。读回来时每个字段都重新校验，缩略图只认 `xingmang-asset://thumb/…/video/{编号}`，并按编号换成现在的缩略图版本（`electron/asset-thumbnail.ts` 一升版，存着的旧地址主进程就不认了）。缩略图出不来（Linux 上取不到视频封面、片段被删了）时不放裂图，留底色、播放键和镜头号。存不下时工作台顶上出一条提示，不影响用，下一次改动时补写。什么都没写的新视频（没想法、没镜头）不存、不列。
- 老版本的草稿（0.2.24 及以前）：手头那一条在 `localStorage` 的 `xingmang-ui-v2:video-studio:{账号}`，草稿箱（最多 20 份）在 `…:drafts`。升级后头一次打开「创作」，`loadVideoStudioLibrary` 把它们各抄一份成文件（手头那一条的编号写死 `legacy-current`，抄到一半重来也不会抄出两份），再读回来逐条核对镜头数、已生成的段数、片名、想法，都对上了才写「抄过了」的记号（`index.json`）；没对上的那几个文件拿掉、这一次照老的那份用（只在内存里），下次打开再抄。已经有文件的不再盖（那份可能是抄过以后又改过的）。老的那两格从头到尾只读，不删不改：退回 0.2.24 时草稿原样在。`project.ts` 里读这两格的函数因此不能改读法。
- 一次只开着一条（`useVideoStudioSession`）：手上有事在跑（写分镜、出片、画图、拼片、接回）时不换到别的视频、不能删它，出片、画图、拼片的结果都按镜头编号挂回「开着的这一条」，换走了就挂不上；这时去看对话、看画布项目不受影响，工作台只是藏起来、不卸载。选图、选歌的对话框开着时换了视频，选回来的不挂到换上来的那一条上。记着请求号的片段读回来是「生成中」，点开那一条时照重开页面那样拿请求号去接回，只查不提交；没点开的不去接。
- 「用一张图开头」（yoyo 2026-11-09「图开头改」）：选图走对话页那条通道（`pickAiChatImages`，原生对话框，图太大主进程先缩好、存进作品库），这里只拿编号，存工程时也只存编号、读回时按编号重拼 `xingmang-asset://image/{编号}`。一次选了几张，第一张给点按钮的那一镜，剩下的按顺序给它后面还没有图、也没在生成的镜头（`assignVideoStudioShotImages`），一次最多 4 张（对话那条的上限）。出片时带 `imageAssetIds`：Grok 拿它当第一帧，MiniMax 从 `t2va` 换成 `i2va`（只收一张图）；主进程本来就收参考图，没加通道。换图不动已经生成好的片段，重新生成才用上；生成着的镜头换不了图。重写分镜时第几镜的图还给新的第几镜（`applyVideoStudioPlan`）。
- 「AI 生成图片」（yoyo 2026-11-09 回「按照你的推荐」批的字，当时叫「让 AI 画一张」；2026-11-22 界面文案正式化第 10 批改名）：先按这一镜的画面描述出一张便宜的图，满意了再拿它出视频。走对话页出图那条（`generateAiImage` / `chat:generate-image`，凭据在主进程、图存进作品库）。点了弹出来的是出图框 `ShotImageDialog.tsx`（融合第 4 步，yoyo 2026-11-20 回「融合改」），跟对话里「生成图片」那一档是同一个：型号、尺寸、画质、分辨率那一排是同一个部件（`chat/ImageOptions.tsx`），记的也是同一份（`chat/image-settings.ts`，按账号记在这台电脑上），在一边改了另一边跟着变；「想法」卡里原来的「画镜头图」型号菜单去掉了。框里先填上这一镜的画面描述，在框里改的只管这一张图、不写回镜头；能加参考图（最多 4 张，型号得会改图）。打开时用哪个型号：记的那一份，没有就这条视频以前选的（`settings.imageModel`，字段还留着、不再有地方改），再没有就出图默认那一档（`videoStudioImageModelChoice`）。尺寸客户没在框里改过时跟「画面」走（`videoStudioImageOptions`）：记的那个横竖对得上就用它，对不上按 `videoStudioImageSize` 另挑（只收固定几种尺寸的挑长宽比最接近的，只有 auto 的交给模型，能自己定的按 720p 算，短边 720，模型上限更小就整体缩）；这样自动挑的尺寸不往共用的那一份里记（`videoStudioImageSettingsToShare`），不然对话里的尺寸会跟着某条视频的横竖变。框左下角报价和余额；画的时候这一镜的描述、图、出视频、删，和「生成全部」「编写分镜」都灰着，画好的图和自己选的一样挂上（`finishVideoStudioShotDrawing` 只认还挂着同一个请求号的那一镜，停了又重画、镜头删了，迟到的结果不会盖上去）。「停止生成图片」走 `chat:cancel`，已经交出去的照样扣费（出图框里说过）；余额、额度不够照页面顶上那条报（带「前往充值」），别的原因写在这一镜下面。画着的状态不存：画到一半关掉软件，图照样进 AI 作品文件夹，但不会挂回这一镜。
- 每个镜头单独定时长（yoyo 2026-11-09 回「所有的修改都按照你的推荐」）：每一镜一个「时长」下拉，只列视频模型能出的那几档。定成和「每段时长」一样就是不单独定（`setVideoStudioShotSeconds` 不存这一项），以后改「每段时长」跟着走；定过的不动。和图一样，重新生成才用上；出着的、排着队的改不了。换视频模型时每段时长和各镜定的时长一起挪到新模型能出的最近一档（`selectVideoStudioVideoModel`），算的时候也再挪一次（`videoStudioShotSeconds`），记着的老数不会原样发出去。长短不一时分镜卡不写「每段 S 秒」，确认框写「生成 N 段、共 T 秒」。
- 剪头剪尾（yoyo 2026-11-09 回「所有的修改都按照你的推荐」）：生成好片段的镜头多两个下拉「开头剪掉」「结尾剪掉」，按档选（不剪 / 0.5 / 1 / 1.5 / 2 / 3 秒，`videoStudioTrimChoices`）。页面里放不了视频，拖动条找不准位置，按档选更好用。剪完至少留 1 秒（按片段时长算，读不到就按「每段时长」），选不了的档不列；拼片时作为 `trimStart` / `trimEnd` 交给引擎（画面和声音一起剪）。跟着片段存进工程、读回时整对校验；换上新片段（重新生成、接回）就清零；剪的长短一变，上一次的成片对不上，不再挂在页面上。分镜卡上「共约 T 秒」减掉剪掉的。
- 字幕大小、位置（yoyo 2026-11-09 回「所有的修改都按照你的推荐」）：开着「加字幕」时「合成视频」卡多两个下拉「字幕大小」小 / 中 / 大、「字幕位置」底部 / 中间 / 顶部，缺省中号、底部，和加这两项以前印出来的一模一样（老工程读回来也是这样）。小号、大号是中号字的 0.8、1.25 倍；顶部竖屏让开状态栏和标题（上八分之一），横屏贴顶留一点边；中间整块居中（`captions.ts` 的 `layoutVideoStudioCaption`）。
- 淡入淡出（yoyo 2026-11-09 回「所有的修改都按照你的推荐」）：「合成视频」卡加「镜头之间」直接切 / 淡入淡出和「结尾淡出」开关，缺省直接切、不淡，跟加这一项以前拼出来的一模一样（老工程读回来也是这样）。淡入淡出是前一段淡到黑、后一段从黑里出来，每一头 0.4 秒；结尾淡出 1 秒；一段太短时每一头最多占三分之一（片尾一半），算法在 `timeline.ts` 的 `buildVideoStudioRenderPlan` / `videoStudioFadeLevel`。画面在字幕画好以后整张盖一层黑，原声按每个采样点的时间跟着同一条曲线淡；配乐不跟着镜头淡，只在结尾照旧淡出 2 秒。
- 「加配乐」（yoyo 2026-11-09「配乐改」）：歌由主进程弹系统对话框选（`pickVideoStudioMusic`，MP3 / M4A / WAV / OGG），照音频作品库那套检查存进去（单链接普通文件、最大 128 MB、按内容认格式），页面只拿编号、歌名（文件名去掉扩展名）和时长；认不出的文件报「这首歌读不出来，换一首试试（支持 MP3、M4A、WAV、OGG）」。拼片时按编号读回来（`readVideoStudioMusic`，和读片段同一队），交给拼片引擎：从成片开头放，比成片短就从头接着放，结尾 2 秒淡出。「片段原声」照常 / 调小 / 关掉，选了歌默认调小，换一首时照旧（两路各放多大见 `project.ts` 的 `clipSoundGains`）。工程里只存编号、歌名、时长和原声那一项；换歌、换原声、不用配乐都会让上一次的成片对不上，不再挂在页面上（文件还在作品库里）。
- 想法和画面描述在发给主进程之前先去掉看不见的控制字符（粘贴带进来的垂直制表这类，换行和制表照留），不然主进程整句拒掉、报一句对不上原因的「想法要写 1 到 2000 个字」。
- 写分镜、拼片的时候不出片（`generate` 开头挡住，同 `writePlan` 那边）：写分镜会把镜头整个换掉，付了钱的片段回来时找不到镜头。拼片读片段时边读边加，加起来超过上限（见下面「上限」）就停在那一段，不把剩下的也读进来。
- 排队、进度不记；已经发出去的那一段记下请求号（没等到结果就失败的也记，服务端可能还在出）。关掉软件或刷新页面再打开，这几段先显示「生成中」，页面拿请求号找主进程接回来（`resumeAiVideo`）：还在出就接着等，已经出完就直接挂回镜头，主进程那边没有这一单就回到「还没生成」。只查不提交，不会再扣一次钱。请求号跟着分镜存在主进程的文件里：页面在发这一单之前先发那一次保存（`urgent`，不等攒批），主进程收到 `video:generate` 后等这一笔写完（`videoStudioProjects.idle()`）才交给服务端，所以刚点完「生成」就强退、崩溃或断电，重开以后请求号也在（0.2.24 深查 KR-4 说的「等分镜搬进主进程再根治」就是这个）。保存自己失败不拦这一单，页面另有「这台电脑上存不下这份分镜」的提示；`flushPageStorage` 那一步还留着，只是尽力。
- 交出去了却没拿到任务号的那一段（回包丢了、服务端出错、提交到一半点了停止、软件被关掉）：主进程照「提交结果不明确」那句报错（`electron/ai-video-submission.ts`，两边共用），镜头记成「结果不明」（`unconfirmed`）连同请求号一起存下。重开以后直接是「没生成出来」加那句提醒，不去接（没有任务号，接不回来），不会变回「还没生成」让「生成剩下的」再付一次钱（#1489 N2）。要再生成，确认框另外说清「钱可能已经扣了，片段却拿不回来，可能多扣一次」，先勾「我已了解影响」才能点；确认后沿用原来的请求号重新提交，MiniMax 拿它去重。这一回没交出去就停下、或者被服务端拒了，上一回那一单照样可能扣了钱：镜头回到失败、提醒照旧（主进程那一笔也不划掉）。
- 失败了还记着请求号的那一镜（「暂时查不到进度」这类，服务端多半还在出），点「重新生成」先拿这个请求号接回：接得回来就不再提交；主进程那边确实没有这一单，才重新提交、重新计费；主进程说这一单提交结果不明确的，停下照上一条提醒，不换新请求号再付。接回时点了停止、主进程又说没有这一单的，不再提交。
- 排队时连同客户在确认框里点头时的设置一起排，轮到哪一段都照那份出（#1489 R28-4）：页面刚打开、模型表还没读完就点了生成，读完以后记着的模型换成了默认的，排在后面的几段也不会悄悄换模型和时长。那个模型真的用不了了，主进程在扣费之前就拒掉。
- 视频模型从账号所有分组里找（`kind` 是 `video` 的，现在是 Grok 和 MiniMax 两家），默认 `grok-imagine-video-1.5`；每段时长只列这个模型能出的长度。文字模型的菜单和聊天一样按厂商分节。
- 对话里出好的一段视频能「添加到视频」（融合第 2 步）：`project.ts` 的 `appendVideoStudioClip` 把它接成这条视频的最后一个镜头（描述进画面描述，片段直接挂上，不用再生成；上一次拼好的成片不再算数），`createVideoStudioProjectFromClip` 是「新建视频」那一项（想法填那句描述，画面比例、出片的模型跟着这一段走，别的设置照最近那一条）。这是从工作台外面改一条视频，走 `useVideoStudioLibrary` 的 `replace`：它给这条视频的版本号加一，开着的工作台按新的版本号重新挂（`CreatePage` 里 `key` 带着 `library.revision(id)`），旧工作台手上那份 `source` 认的是发给它时的版本号，之后再写一律不收，不会把新加的镜头盖回去。那条视频正开着、手上有事（写分镜、生成、拼片）时不加（出好的东西要挂回它身上），镜头放满了也不加，各说一句。
- 作品库里现成的东西能直接用在镜头上（融合第 3 步，按钮只在「创作」页把 `library`（`VideoStudioLibraryPicker`）交下来时出现）：「从作品库选图」选一张当这一镜的开头图（跟「用一张图开头」落在同一格，只存编号）；「使用已有片段」把一段现成的视频挂到这一镜上，镜头记 `borrowed: true`（`project.ts` 的 `assignVideoStudioShotClip`），不用生成、不花钱。用着现成片段的镜头状态牌写「已有片段」，那一排是「更换片段」「不使用此片段」（`removeVideoStudioShotClip`，回到「还没生成」），没有「生成」和「时长」；算总时长、算几镜一样长时按片段自己的长度（`videoStudioShotLength`）。第 2 步「添加到视频」接进来的那一段、起始页第三张卡「用已有片段合成视频」新开的每一镜（`createVideoStudioProjectFromClips`）也都记 `borrowed`。这个记号还有一个用处：作品库认一段视频「出自」哪条视频时，只认生成它的那一条，接进去用的那些条算「用于」（`features/create/library.ts`）。选择框由「创作」页开（`features/create/CreateLibrary.tsx` 的 `LibraryPicker`），工作台只等它交回编号；等的时候换成了别的视频，选好的不挂到换上来的那一条上。
- 换账号时整页重新挂载（`key={scope}`），上一个账号的请求和进度都作废。

文件：

- `project.ts` — 纯函数：工程的形状、默认值、分镜落成镜头、排序增删、出片段的请求、序列化和校验，以及 0.2.24 那两格 `localStorage` 的读法。
- `library.ts` — 纯函数：一条视频一个文件的内容、名字、排序，老草稿怎么抄、抄完怎么核对。
- `useVideoStudioLibrary.ts` — 这个账号的全部视频（读、攒着写、改名、删、从工作台外面整份换掉）和「现在开着哪一条」。
- `clip.ts` — 纯函数：存着的一段视频怎么读回来（编号、请求号、缩略图地址都重新校验，镜头和对话里出的视频共用），页面里直接放用的地址（`xingmang-asset://video/<编号>`）。
- `useVideoStudio.ts` — 一条视频的状态和对主进程的调用：读模型、写分镜、排队出片段、拼片；工程从「创作」交来的 `source` 读、往它写。
- `VideoStudioPage.tsx` / `video-studio.css` — 工作台本身。

## 主进程那一半

请求都在主进程发，凭据和文件路径不出主进程（`electron/ipc/handlers/ai-video.ts`）：

- `planVideoStudio`：文字型号把一句想法拆成几个镜头，每个镜头一句给视频型号的画面描述和一句字幕（`electron/video-studio-plan.ts`，上限页面也从这里读）。
- `generateAiVideo`：出一段视频，存进全局作品库后回编号、缩略图、宽高和时长；进度经 `onAiVideoProgress` 推回来。只有视频剪辑页用这一条。主进程照画布那套按窗口兜一层（同时最多 20 段在出、每分钟最多 80 次，`canvas-generation-admission.ts`），页面出错或被投毒也不能连发付费视频；每一单等完（出好、失败、停下）提醒主窗口刷新余额，同聊天、生图。
- `resumeAiVideo`：按请求号接回上次没等到的那一段。主进程的任务记录里本来就带着请求号；取回来存进作品库时另记一笔「请求号 → 片段」（`ai-video-task-store.ts` 的 `finish`，只留最近 100 条），所以开机续查已经把片段取回来了，页面晚些打开也对得上。每一单交出去之前先在同一个文件里记一笔「已发出、还没拿到任务号」（`markUnconfirmed`，只留最近 100 条），拿到任务号或服务端明确拒掉时划掉（沿用请求号重新提交的那一回，上一回留下的那一笔只在拿到任务号时划掉）；按请求号接回时碰到它，照「提交结果不明确」报错，不回「没有这一单」。这一笔写不进不拦这次出片，只是少了这层提醒。同一个服务端任务不管是出片段那次、开机续查还是页面接回在等，只查一份、只存一个文件（`ai-video-service.ts` 的 `finishOnce`）。
- `cancelAiVideo`：停下分镜、出视频或接回。已经交给服务端的视频照样生成、照样扣费，下次登录会自己取回来。
- `readAiVideoClip`：读一段视频的全部字节，交给下面的拼片引擎。
- `generateAiImage` / `cancelAiChat`：对话页出图那两条，「AI 生成图片」照用，没加通道。
- `pickVideoStudioMusic` / `readVideoStudioMusic`：选一首歌存进作品库的音频那一格（路径来自系统对话框，不来自页面），拼片时按编号读回来。
- `storeVideoStudioExport`：拼好的成片存进作品库；`openAiVideo` 用电脑默认的播放器打开，`saveAiVideo` 另存（页面把片名带过去当系统对话框里默认的文件名，主进程 `parseVideoSaveName` 洗成干净的文件名：路径分隔符和 Windows 不认的字换成空格、去掉改写显示方向的字、最长 80 个字、接 .mp4，保留名或洗空了就用作品库原来的名字；存到哪儿照旧由用户在对话框里点）。读片段和存成片在主进程按窗口排成一队、一次只搬一段（最多 512 MB），排着的超过 12 个直接拒，连发也撑不爆主进程内存。
- `openDiagnosticFolder('ai-output')`：检查页那条通道，打开 AI 作品文件夹（路径由主进程算，过了 I8 检查才打开）。成片那一行和说到「AI 作品文件夹」的提示旁边都有「打开文件夹」，打不开时按失败说一句。

主窗口的 CSP 只有一条 `media-src xingmang-asset:`（融合第 2 步加的，产品负责人 2026-11-09「看片放开」：只放作品库里当前账号的音视频，不许再扩大），对话里出好的一段视频、作品库里点开的一段视频（融合第 3 步，同一条、没有再放宽；第 5 步起作品库里也列画布项目里生成的视频，放的仍只是当前账号自己的，CSP 没改）点了能在页面里放（`clip.ts` 的 `videoClipPlayUrl`）；这一页自己还是缩略图加「用播放器打开」。打包版里 `xingmang://` 回的每个文件都带上和 `index.html` 一样的 CSP 响应头（`electron/app-protocol.ts`）：拼片的后台线程只认自己脚本的响应头、不继承页面的 `<meta>`，这样它也连不了外站。

凭据门禁（`scripts/verify-canvas-renderer-boundary.test.cjs`）同样扫本目录和对话页，页面或线程里长出带 Key 的请求会当场红。

## 拼片引擎

`composeInVideoStudioWorker(request, { signal, onProgress })` 在后台线程里拼，页面不卡；`composeVideoStudio` 是同一套，直接在当前线程跑（测试用）。

- **输入**：每段片段的全部字节（MP4 / MOV / WebM）加可选的剪头、剪尾、字幕；镜头之间直接切还是淡入淡出、结尾淡不淡出（缺省直接切、不淡）、字幕大小和位置（缺省中号、底部）；可选的配乐（一首歌的全部字节和音量）和片段原声的音量（缺省 1，0 就不要原声）；成片的画面比例（16:9、9:16、1:1）、清晰度（短边 480 / 720 / 1080）、填充方式（裁边 `cover` / 补黑边 `contain`）和帧率（24 / 25 / 30）。
- **输出**：一个 MP4 的字节、编码、宽高和时长。画面优先 H.264，没有再用 VP9、AV1；声音优先 AAC，Linux 的 Chromium 没有 AAC 编码器，用 Opus。所有片段都没有声音（或原声关掉）又没配乐时成片不带音轨。
- **字节会转移**：交给后台线程后 `request` 里的 `ArrayBuffer` 就空了，要重拼就重新读片段。
- **不装 ffmpeg**：解码、编码都用 Electron 自带的 WebCodecs，读写 MP4 用 [mediabunny](https://github.com/Vanilagy/mediabunny)（MPL-2.0，没改它的源码）。
- **上限**：最多 50 段、成片最长 10 分钟、一段最大 512 MB、配乐最大 128 MB；加起来最大是这台电脑内存的八分之一，夹在 256 MB 到 1 GB 之间（`videoStudioTotalBytesLimit`，内存数取 `navigator.deviceMemory`，读不到按 1 GB）。片段和成片整个在内存里组装，一次拼片吃的内存是片段合计的两三倍，所以内存小的电脑放得少；导入本地长视频开工前要改成主进程按需读片段、成片直接写临时文件。

文件：

- `timeline.ts` — 纯计算：成片尺寸、每段从哪儿取、落在成片第几帧。按整帧切，48 kHz 能被每个帧率整除，所以画面和声音拼多少段都不会错开。
- `captions.ts` — 字幕排版：汉字按字断行、英文按词断行，标点不上行首；字号按短边算，竖屏抬到下五分之一；放不下先缩字号再截断。
- `pcm.ts` — 声音拼接：每段先重采样成 48 kHz 立体声再交给编码器，只写这一段自己的时间窗，没有声音的地方是静音。
- `music.ts` — 配乐：跟着声音块的顺序往下解这首歌（不回头，整首不必一次解进内存），放完从头再来，结尾淡出，混进原声后截到满格以内。
- `encoding.ts` — 挑这台电脑能用的编码器。
- `compose.ts` — 用 mediabunny 读片段、逐帧画到画布上烧字幕、编码、写 MP4。
- `compose-protocol.ts` — 后台线程两头的消息格式，两边都按白名单读。
- `compose-worker.ts` / `compose-client.ts` — 后台线程本身和页面这一头；取消就直接关掉线程。
- `errors.ts` — 报错上屏一律中文；浏览器抛的英文错误换成一句能照着做的话。

## 验证

```bash
npx vitest run src/renderer-v2/features/video-studio --no-file-parallelism
XINGMANG_E2E_CHROMIUM=/opt/pw-browsers/chromium node --test src/renderer-v2/features/video-studio/browser-check.mjs
```

浏览器测试在页面里现做几段纯色片段（不同尺寸、帧率、有无声音），拼完再解出来量颜色、字幕像素和音量，也核对后台线程、取消和读不了的文件。页面那几条（`page-fixture.html`）用假的主进程桥走完写分镜、生成、拼片、刷新后恢复，生成到一半刷新后接回片段，以及停下分镜和正在生成的片段。不碰网络。

Windows / Mac 上能不能编出 AAC 声音要真机看；编不出也会自动换 Opus，照样出 MP4。
