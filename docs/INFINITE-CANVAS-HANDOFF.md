## 2. 产品方向与已经确定的原则

无限画布不是一个单纯的白板，也不是把某个 GitHub 项目换皮。它是星芒 AI 管理工具箱内的本地优先、节点式 AI 媒体生产工作台。

当前已经确定、后续不应随意推翻的原则：

1. 画布默认使用中性暗色系，禁止白色首帧和大面积亮色节点。
2. `@xyflow/react` 是唯一画布内核，不再同时引入另一套画布引擎。
3. API Key、access token、refresh token 和供应商请求只存在于 Electron 主进程。
4. Renderer 只提交分组、模型、提示词、受限参数、稳定资产 ID 和工作流图。
5. 节点按媒体能力设计，不为每个供应商复制一套节点目录。
6. 每次运行产出的最新候选自动成为节点产物（**老板 2026-08-20 产品决策，推翻原「先候选、后采纳」原则**）。原则改为：生成完成即固定，节点上不再有「采纳此候选」「丢弃」两个按钮。成立的前提是另外两条不能弱化——运行历史仍然逐条保留每一次 attempt 与全部候选，旧图可从运行检查器回溯并重新设为产物；自动固定只标记下游为脏，绝不自动发起新的付费请求。
7. 切换产物（自动固定或用户在运行检查器里改选）只标记下游为脏，不自动触发新的付费请求。
8. 工作流和项目文件不保存 API Key、会话、远程临时 URL、base64 大图或本地绝对路径。
9. 新建画布项目必须选择工作文件夹；该项目的图片、视频、音频统一落到 `<工作文件夹>/assets/`，工作流只保存 `assetId`。非画布 AI 聊天继续使用安装根目录的 `output/`。
10. 不支持从远程 URL 下载并执行任意 JavaScript 插件。
11. 不能通过“融合多个项目”规避许可证。受限或无许可证项目只能用于形成行为需求和独立验收测试。
12. 自动化测试不请求生产 `xm.solov.cc`；生产联调必须单独、受控执行。
13. 资产 ID、受信本地 URL 和物理文件名是稳定身份，用户重命名只更新账号与项目隔离的逻辑 `displayName`，不能移动或改写媒体文件。
14. 付费媒体请求必须由主进程从已校验的节点参数构造；renderer 不能自行拼接 `/v1/videos` 请求，也不能把远程图片 URL 作为视频参考图绕过本地所有权校验。

当前版本明确不以以下能力为交付目标：完整多轨非编时间线、多人实时 CRDT、远程插件市场、3D 导演工具、云端共享协作。

### 2.1 主应用与画布的统一视觉原则

用户提供的 UI 方法文档推荐 shadcn-admin、Tailwind CSS 和 shadcn/ui。这里吸收的是它们成熟的设计系统方法，不把现有 Electron 应用整体迁移到另一套 CSS 技术栈。仓库已经有稳定的 React 组件、全局语义令牌和大量视觉回归测试，全量迁移的收益不足以覆盖回归风险。

主应用和画布后续共同遵守：

- 桌面工具采用“侧栏 + 顶栏 + 内容工作区”的安静、紧凑布局，首屏直接进入工作，不做营销式 Hero。
- 亮色主题使用低饱和中性灰表面、白色内容面板和青绿色强调色；暗色主题使用 `#111315` 附近的中性底色，不做大面积蓝紫染色。
- 页面标题保持 20px 左右的工作区层级；面板标题更小、更紧，避免在卡片内使用展示型大字号。
- 卡片只用于独立、重复或确实需要边界的对象；页面章节保持无框或单层面板，禁止卡片套卡片。
- 圆角不超过 8px；阴影只用于弹窗、菜单等浮层，常驻面板依靠边框和表面层级区分。
- 图标按钮优先使用 Lucide，必须有 `title` 或可访问名称；二元设置用开关，模式切换用分段控件，选项集用下拉菜单。
- 导航、工具栏、节点和媒体预览都使用稳定尺寸，loading、状态文字和长名称不能造成布局跳动。
- 亮暗主题必须共用语义令牌，不在业务组件中复制两套颜色；状态不能只靠颜色表达。
- 1590x875 是默认桌面窗口验收尺寸，同时必须覆盖 960x620 紧凑窗口和高 DPI 缩放。

当前主应用的实现策略是继续使用 `src/styles.css` 的两层令牌，先收口 AppFrame、Sidebar、公共 page/header、表单和面板层级，再逐页消除遗留硬编码。不要同时引入 Tailwind 和现有全局 CSS 两套真相源。

## 4. 当前架构

```text
主应用账号会话
  access/refresh token、API Key 管理、可用分组
                 |
                 v
ChatCredentialCoordinator
  分组检查 -> 复用或自动创建 Key -> 本机加密缓存
                 |
                 v
Electron main
  sender 校验 / 字段白名单 / DAG 调度 / 运行记录
  AiImageService / AiAssetStore / ProjectPackage / PromptPresetStore
                 |
        narrow typed IPC，绝不传 Key
                 |
                 v
Canvas renderer（sandbox + contextIsolation）
  React Flow / 节点 UI / 编辑命令 / schema v2 / assetId
                 |
                 v
xm.solov.cc + <画布项目工作文件夹>/assets
```

安全边界：

- 画布窗口启用 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`。
- CSP 使用 `connect-src 'none'`，renderer 不能直接请求生产网络。
- IPC sender、字段、长度、数量、文件路径和账号所有权由主进程校验。
- 账号切换会取消旧账号的生图和画布运行，并重新初始化新账号的运行记录和资产索引。
- 运行错误在保存或发往 renderer 前清除 Bearer、Key、URL、本地路径和控制字符。

### 4.1 new-api 图像与视频协议契约

`xm.solov.cc` 当前部署 new-api，Base URL 为 `https://xm.solov.cc`。画布 renderer 不直接调用这些端点；以下协议由 Electron 主进程服务实现，renderer 只经窄 IPC 传入已校验的业务字段。

#### 图像生成

- 文生图：`POST /v1/images/generations`，JSON 请求。
- 图像编辑：`POST /v1/images/edits`，必须为 multipart；图片字段使用 `image` 或重复的 `image[]`，不能使用 `images`。
- 图像请求超时至少 300 秒；不自动重放结果不明确的付费请求。
- `gpt-image-2` 的宽高都必须是 16 的倍数，`quality` 必须显式传入，默认 `low`，可选 `low/medium/high/auto`。
- `grok-imagine-image`、`grok-imagine-image-2.0`、`grok-imagine-image-quality` 不传 `size` 和 `quality`，支持图像编辑。
- 即梦模型不传 `quality`；响应中的临时 URL 必须立即由主进程下载落地，不能作为长期资产引用。
- 响应同时支持 `b64_json` 与 `url`；无论来源如何，最终都转换为本机账号专属 `assetId`。
- 参考图、MIME、文件签名、数量和总字节数在付费请求前校验；4K 原图不直接作为画布缩略图渲染。

#### 视频生成

- 提交：`POST /v1/videos`。
- 查询：`GET /v1/videos/{id}`。
- 下载：`GET /v1/videos/{id}/content`。
- 模型为 `grok-imagine-video` 和 `grok-imagine-video-1.5`。
- `seconds` 按字符串发送，上限 15；本地图生视频输入转换为受控 data URI，建议不超过 8 MB。
- 提交成功后必须立即持久化本站返回的任务 `id`。`task_id` 是上游标识，不作为恢复查询的主键。
- 轮询和内容下载可以做有界指数退避；付费提交在超时、断线或结果不明确时绝不自动重发。
- 状态至少归一化为 `queued/in_progress/completed/failed/cancelled`。停止等待不等于取消上游任务，UI 必须提示任务可能仍在生成。
- 完成后 MP4 下载到 `<画布项目工作文件夹>/assets/user-<id>/<日期>/`，任务记录同时持久化 `projectId`，重启续查仍写回原项目；只通过受信本地协议播放。

#### 分组 Key 与模型预检

推荐映射是：

| 能力 | 首选分组 | 典型模型 |
|---|---|---|
| GPT Image / 即梦 | `生图分组` | `gpt-image-2`、即梦 |
| Grok 图片 | `grok-image` 或 `grok` | `grok-imagine-image*` |
| Grok 视频 | `grok` | `grok-imagine-video*` |

切换分组时由 `ChatCredentialCoordinator.prepareGroup` 检查本机加密缓存和服务器 Key；没有可用 Key 时自动创建，确认 401/403 鉴权失效后清缓存并重新签发。同一账号和分组的并发准备必须合并。renderer 只能看到分组、模型、能力和是否创建了 Key，永远看不到 Key 明文。

模型目录要提供统一能力矩阵，至少覆盖 operation、模型、分组、尺寸、画质、参考图数量、视频时长和输入媒体上限。所有可静态判断的不兼容组合必须在付费请求前阻止。

### 5.4 分组、模型和 API Key

- 画布复用当前登录的星芒账号。
- 可列出账号可用分组并切换分组。
- 切换分组时调用 `prepareGroup`；若该分组没有可用 Key，会通过账号后端复用或自动创建 Key。
- Key 按账号和分组加密存到本机，后续优先读取缓存。
- 缓存 Key 被撤销或确认鉴权失败时会清理并重新签发。
- 同一账号/分组的并发初始化会合并，避免重复创建 Key。
- Renderer 只收到分组名、模型列表、是否创建 Key 和非敏感存储警告，不收到 Key 明文。
- 画布顶部的“生成配置”分别选择生图分组和视频分组，并展示各自真实可用的模型数量与模型名称。
- 图像和视频节点只展示对应分组由服务端返回、且客户端已验证能力的模型；切换分组后不兼容的旧模型会明确标记并禁止运行。
- 分组是 `CanvasDocumentState` 的组成部分，切组和项目替换会与节点一起进入 Undo/Redo 历史，避免节点与凭据分组错配。
- 初始化、手动切组、项目恢复共用 latest-request revision；旧请求和旧 `finally` 不能覆盖新选择或提前解除运行门禁。
- 打开或导入项目时，图片和视频分组会先并行验证并准备成功，再把节点与两组配置一次写入文档；任一分组失败时保留原项目，不形成半恢复状态。
- 工作流运行只检查 `all`、`selection`、`dirty`、`to-node` 实际执行闭包中的非禁用媒体节点，且分组缺失或模型不属于该分组时会在付费 IPC 前阻止。
- `.xingcanvas` 通过 `mediaGroups.image` / `mediaGroups.video` 保存项目分组偏好；文件中不保存 API Key、token 或其他凭据。

- 提示词输入。

- Router/Gallery/Output 的当前透传语义。

当前会明确拒绝且不会伪造成功：

- 视频抽帧。
- 未绑定执行器的其他能力。

- 分支失败传播，独立分支可继续完成。
- 用户取消、cancelling 状态、迟到结果抑制。
- 每个节点终态只提交一次。
- `runId`、`attemptId`、`graphRevision` 和递增事件序列。
- 输入指纹缓存，避免未变化上游重复付费。
- attempt、候选、耗时、分组、模型、quota 和清理后的错误记录。
- 当前账号专属运行历史、缓存和资产清单。

### 5.6 候选与结果

> **2026-08-20 产品决策（老板拍板）：候选不再需要采纳。** 老板真机试用后判定
> 「先候选、后采纳」是多余的一步：图已经生成出来了，下游却显示「等待上游产物」。
> 新语义是每次运行的最新候选自动成为节点产物。本节与 §2 原则 6 一并改写，旧描述
> 不再适用。

- 每次执行形成不可变 attempt。
- 一个 attempt 可包含多个同级候选。
- **每次运行产出的最新候选自动成为 `data.result`**：取最新一次真正产出候选的 attempt 的首个候选。节点上没有「采纳此候选」与「丢弃」，重跑入口是运行按钮与媒体操作条上的「重新生成」。
- **运行历史保留每一次 attempt 与全部候选**（节点上最多投影 16 个），旧图可从运行检查器回溯并「设为产物」。这是自动覆盖能被接受的前提，不得弱化。
- **切换产物只标记下游 dirty，绝不自动发起新的付费请求。** 自动固定同理：参与了本次运行的下游节点保持它们自己的运行结果（它们本来就是拿着新产物跑完的），运行范围之外的下游才被标记为待重新运行。
- 用户已经在运行检查器里切到同一次 attempt 的另一个候选时，重复投影同一条运行记录不会把产物拨回首个候选；换了新的 attempt 一律覆盖。
- Output 节点只有两种表达：有产物（「最终产物已就绪」）与没有产物（「连接上游后运行」）。原先的「待确认结果」随采纳步骤一并取消。
- 旧产物在下游重新运行前仍保留，避免编辑过程中突然消失；生成失败或取消不会抹掉上一次的产物。
- 运行检查器支持按媒体类型检查候选；图片单击即设为产物、双击放大，视频保留控件并支持放大，音频使用独立音频控件和灯箱。当前产物那一张有独立描边与「当前产物」标示。
- 输入节点的已绑定资产与生成结果使用同一套本地媒体预览入口；替换素材会沿用现有下游 dirty 标记，不改变执行协议。
- 候选支持复制、另存和在文件夹中定位。

### 5.7 本地资产

- 新建项目时必须通过系统目录选择器指定工作文件夹；取消选择不会创建项目。
- 该项目生成的图片、视频以及导入的图片、视频、音频保存到 `<工作文件夹>/assets/user-<id>/<日期>/`，不同项目的素材列表和落盘目录相互隔离。
- AI 聊天等非画布功能仍保存到 `<安装根目录>/output/user-<id>/<日期>/`，项目目录切换不会改变其行为。
- 旧画布项目没有工作文件夹元数据时继续兼容原全局素材库，不会伪造或向 renderer 暴露本地路径。
- 图片支持 PNG、JPEG、WebP 文件签名和 MIME 校验；视频支持 MP4；音频支持 MP3、WAV、OGG、M4A。三类素材都执行内容签名和账号所有权校验。
- 单张图片上限 64 MB。
- 图片、MP4 视频和音频都可从系统文件选择，也可从操作系统拖入软件；导入后分别创建对应的图片、视频或音频输入节点。
- 本地媒体使用项目资产根目录、账号和文件内容生成稳定资产 ID；同一项目、同一账号重复导入相同内容会复用同一资产，不会在资产栏新增重复项。
- 历史随机 ID 产生的同内容重复文件只在资产列表按内容折叠，不删除磁盘文件，旧节点、运行记录和旧资产 ID 仍可继续读取。
- 素材显示名称保存在各资产根目录的账号级 `asset-metadata.json` 中；同一资产 ID 在不同账号或不同项目可以有不同名称，搜索会同时匹配逻辑名称、物理文件名和资产 ID。
- 重命名前必须从当前资产上下文执行所有权读取；名称限制为 1-120 字符并拒绝控制字符和路径字符，物理 `xingmang-<assetId>.<ext>` 文件名、`assetId` 和 `localUrl` 始终不变。
- 图片、视频和音频由统一媒体资产服务分页、搜索和筛选，默认每页 24，单页上限 100。
- 当前索引最多扫描 500 个当前账号资产。
- 已有图片/视频/音频混合资产分页、搜索、筛选和稳定元数据测试。
- 图片支持复制、另存和在文件夹中显示；视频和音频支持另存和在文件夹中显示。
- 生成资产可展示来源节点、运行、attempt、候选、项目和最多 256 个上游资产 ID；素材详情可定位回来源节点。
- 素材引用检查由主进程汇总当前画布、全部账号自有项目、运行输入和候选，采用有界精确 `assetId` 匹配，不用提示词子串或 renderer 推断决定是否可删。
- 当前引用检查是只读保护：无论是否发现引用都不会删除文件。真实删除必须先完成回收站、恢复、并发与运行历史清理语义。
- 账号切换和导入失败会清理本次操作产生的孤立资产。

### 5.8 工作流与项目包

- 工作流 schema 当前为 v2，支持 v1 迁移。
- 上限为 5,000 节点和 20,000 连线。
- 读取链路是 parse -> migrate -> sanitize -> validate。
- 会处理重复 ID、悬空边、未知节点、无效端口、非有限坐标、环和超长字段。
- 普通“打开/保存”使用轻量 JSON 工作流。
- `.xingcanvas` 当前是**有界 JSON 项目包**，不是 ZIP。
- 项目包上限 96 MB、最多 64 个图片资产、单资产 64 MB、工作流 20 MB。
- 导入前显示名称、节点数、连线数、资产数和警告。
- 导入验证字段白名单、SHA-256、MIME、文件签名和敏感字段。
- 导入使用预览、暂存、资产 ID 重映射、原子提交和失败回滚。
- 当前只内嵌图片；视频和音频引用会安全保留，但不会作为二进制资产进入项目包。
- 桌面画布首次进入先显示账号隔离的项目中心。新建项目先选择专属工作文件夹；项目记录节点、连线、视口和图片/视频分组，编辑后 800ms 防抖自动保存，返回项目中心前强制刷新最后一版。
- 项目最多 100 个，同一账号不能让两个项目绑定同一工作文件夹。主进程使用原子写入并按账号串行保存、重命名和归档，避免 800ms 自动保存覆盖项目元数据；渲染进程只持有项目 ID、文件夹显示名称和 JSON，不接触磁盘绝对路径。
- 项目中心按 `lastOpenedAt` 排序，展示预览、节点数、已采纳素材数以及 `ready/missing/legacy` 目录健康。目录缺失和已归档项目禁止打开/保存，旧 v1/v2 记录仍可读取。
- 复制项目要求新的空工作目录，复制工作流与 `assets/`，拒绝符号链接、目录联接和非普通文件；复制失败会回滚目标 `assets/`，不删除目标目录中的既有用户文件。

### 5.10 快速创建与运行范围

- 快速创建支持方向键、Enter、Escape 和外部点击关闭，不从文本输入框抢占快捷键。
- 端口连线落在空白处时复用同一快速创建面板，但只显示与待连接端口兼容的节点；从 source 或 target 两个方向开始都受同一端口校验约束。
- 顶部运行按钮直接显示当前范围：全部、变更、选中链路或运行到节点；右侧菜单同步显示数量和不可用原因。
- 运行范围仍由既有 `CanvasRunScope` 和实际上游闭包计算，UI 没有另建一套运行语义。
- 空画布只显示从模板开始、新建生成节点和打开项目三个操作，不放营销文案。

### 5.11 上游媒体引用与提示词 `@`

- 图像编辑只接受文本和多个图片上游，不暴露视频或音频输入端口；视频生成接受多个文本、图片和音频上游，不暴露当前协议不支持的视频输入端口。两类节点会把各自允许的直接媒体上游投影成“上游素材”区域，显示真实素材名称、媒体类型、就绪/等待状态和安全本地预览。
- 引用投影只读取显式连线和 `xingmang-asset://` 本地资产，不扫描磁盘路径，也不会因为预览缺失重新请求或重新付费。
- 提示词输入 `@` 后只列出当前节点已经显式连接的上游媒体；支持搜索、上下方向键、Enter/Tab 选择和 Escape 关闭。
- mention 的可读标识由节点类型、媒体类型和稳定节点哈希组成。同一工作流内重复投影保持稳定，边仍是执行依赖的唯一事实源；mention 只是提示词编辑辅助，不会隐式创建连线或绕过端口校验。
- 当前执行闭环中，图像编辑可把 1-4 张图片作为 `sourceAssetIds` 提交；视频生成虽然允许多图片连线，但 new-api 当前只接受一个 `input_reference`，因此稳定选择第一张就绪图片作为 `imageAssetId`。音频卡片目前表达显式上游关系，现有 Grok 视频协议没有声明参考音频输入，因此不会伪装为已经提交给模型。
- 旧项目里指向图像编辑或视频生成的单图端口 `in:image` 会在读取时迁移为多图端口 `in:images`；其他节点原有的单图端口语义保持不变。
- 已插入提示词的 mention 是普通文本。删除或重建连线不会自动改写既有提示词；如果后续需要可重命名、可重映射的语义引用，应新增结构化引用字段和迁移，不能靠解析显示文案实现。

### 5.12 图片比例与视频尺寸

- 图片节点继续以受模型能力约束的 `size` 为持久化事实；常用尺寸已经有 `1:1`、`4:3`、`3:4`、`16:9`、`9:16` 等用户可读比例映射。
- 视频尺寸同样复用工作流 `data.size`，可随 schema v2 保存、恢复并进入运行图。当前白名单为 `1280x720`、`720x1280`、`1024x1024`、`1024x768`、`768x1024`，默认 `1280x720`。
- Electron 视频执行器在付费请求前把 `size` 转为 `width`/`height`；IPC 要求宽高成对出现并命中白名单，`AiVideoService` 最终把两字段写入 `/v1/videos` JSON body。
- 图片生成结果和图片编辑结果均已通过真实运行引擎测试，可作为下游视频生成节点的 `imageAssetId`；该链路同时携带项目 ID，参考图从当前账号、当前项目资产目录读取。
- 图片尺寸下拉直接显示“比例 · 像素尺寸”；视频节点提供模型、比例和时长控件，比例选项会按当前模型能力过滤，并继续写入 `data.size`，没有新增第二套比例状态。
- 图片和视频素材预览使用资产记录中的真实 `width`/`height` 计算节点尺寸；媒体加载后发现旧记录缺少尺寸时，会按资产 ID 回写真实元数据并更新节点，而不是依赖固定卡片比例。输入节点与生成结果预览共用同一比例计算，生成视频在元数据尚未到达时先使用节点 `size`（例如 `720x1280`）预留比例，普通视频缺失元数据时才回退 `16:9`、图片回退 `1:1`；真实 `448x672` 竖屏 MP4 在首次导入和项目重开后均已验证为 `320x480` 节点。

### 6.4 模型能力校验

节点定义已经声明 capability，分组也能返回模型列表。当前静态能力矩阵已覆盖 GPT Image、即梦、Grok 图片和 Grok 视频，能够在付费请求前校验操作类型、尺寸、画质、参考图数量和视频时长；节点 UI 会按模型隐藏不支持的 `size`/`quality`，并为视频提供 `seconds` 选择。画布已把生图和视频分组拆开，并将各自服务端模型列表与能力矩阵取交集；主进程在付费 POST 前再次确认请求模型确实属于所选分组。

剩余工作不是重新实现模型归属或静态预检，而是把渠道能力元数据、耗时和费用风险统一投影到同一能力来源，减少服务端能力变化后客户端预设滞后的窗口。未知模型不能根据静态默认值宣称一定兼容，也不能绕过分组模型目录进入付费请求。

### 6.5 长任务恢复边界

运行记录能持久化，应用重启会把普通 running 状态标记为 interrupted。这能防止同步付费请求被误重放；异步视频已经使用独立任务存储和恢复路径：

- 提交成功立即保存服务器任务 ID，允许重启续查。
- 恢复过程只做幂等状态查询，不重新付费。
- 完成后下载内容；内容下载失败可以安全重试。
- 本地 MP4 通过签名、MIME 和账号所有权校验后原子落盘。
- 用户停止等待时保留“服务端可能仍在生成”的语义，任务仍可在后续启动恢复。
- 视频付费 POST 前按账号原子预留恢复槽位；`persisted tasks + reservations` 上限为 200，拿到合法任务 ID 后才把 reservation 转成持久任务，失败和取消路径幂等释放。

任务记录至少持久化账号所有者、节点、attempt、分组、模型、服务器任务 ID、提交时间、最后状态和目标媒体类型，不保存 Key 或可用作鉴权的 URL。账号切换后的迟到结果不能进入新账号资产目录。

## 7. 当前缺口与技术债

### P0：先收口现有架构

1. **补全 command 接管的全入口 smoke**：现有四视口、快速创建、运行范围和 100 节点压力已经通过，下一步覆盖复制、分组、项目导入、Undo/Redo 和运行投影，确认没有结构写入旁路。

8. **图交互剩余收口**：拖线到空白处创建兼容节点已经完成；下一步补“在已有连线上插入节点”、节点/连线专属右键命令和对应真实 Electron smoke。所有结构修改仍必须经过 command/history。

## 15. 可直接接续的任务分解

为避免后续再次从聊天记录拼上下文，按依赖顺序执行：

1. **动态能力目录**：保留已经通过测试的 Grok 图片/视频、`seconds`、状态、响应大小和 MIME 静态规则；增加分组实时模型能力同步、未知模型降级和缓存失效策略。
2. **视频链路回归门禁**：为现有提交、查询、下载、停止等待和重启续查补 Electron 端到端 smoke，证明付费 POST 只发生一次。
3. **视频素材深化**：现有素材库、筛选、画布创建、本地预览、另存、定位和 `video-input` 生产执行保持不变；接通项目包内嵌、poster 和播放错误状态，抽帧在正式接入前继续安全拒绝。

6. **架构收口验收**：跑完 command store 与 renderer registry 的全入口 smoke，修复任何仍绕过 command 的结构写入。
7. **组件拆分**：把画布 `App.tsx` 拆成文档、运行、资产、长任务控制器和纯布局层；瞬态 selection/hover/panel 状态不进入历史。

9. **视觉与交互验收**：维持画布四视口、双主题、缩放、100 节点压力和 canvas-pixel 非空检查；把主应用 smoke 扩展到 960x620 与 Windows 125%/150%。

### 15.1 中长期规划保留项
