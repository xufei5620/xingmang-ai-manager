# 视频剪辑

把 AI 生成的几段片段拼成一条成片。第 1 期「一句话出片」分三步做：本目录的拼片引擎、主进程的分镜和出片段通道、侧栏「视频剪辑」页，三步都已接上。

## 页面

侧栏工作组画布后面的「视频剪辑」（`registry/pages.ts` 的 `video`，T1）。历史账号登录时侧栏和顶部搜索都不出这一项（`App.tsx` 的 `pageVisible`，历史账号站没有视频模型）；没登录时页里只有「登录后才能用」。

流程：写一句想法 → 「写分镜」（文字模型拆成几个镜头，每个镜头一句画面描述和一句字幕）→ 改描述、字幕，上移、下移、删掉、加镜头 → 「生成全部 N 段」（先确认几段、每段几秒、按段计费；同时最多 3 段）→ 某段不满意单独「重新生成」→ 「拼成一条视频」（在这台电脑上拼，不花钱）→ 用播放器打开、另存，或「打开文件夹」到 AI 作品文件夹里找。

- 每一笔要花钱的操作（生成、重新生成）都先弹确认；停下时说清哪几段已经交给服务端、照样扣费。
- 「停止生成」只停排着队的和还没交给服务端的。已经交出去的那几段钱已经扣了、停不下来：镜头上照旧是「生成中」，页面拿原来的请求号接着等（`resumeAiVideo`），好了挂回原来的镜头，不会变回「还没生成」让「生成剩下的」再付一次钱（#1406 P1-1）。主进程那边拿不到这一单（停在提交到一半）的，按主进程那句「提交结果不明确」算失败。在接回的这几单再点停止也不去碰它们。
- 工程（想法、设置、分镜、片段和成片的编号）按账号存在这个窗口的 `localStorage`（`xingmang-ui-v2:video-studio:{账号}`）；读回来时每个字段都重新校验，缩略图只认 `xingmang-asset://thumb/…/video/{编号}`，并按编号换成现在的缩略图版本（`electron/asset-thumbnail.ts` 一升版，存着的旧地址主进程就不认了）。缩略图出不来（Linux 上取不到视频封面、片段被删了）时不放裂图，留底色、播放键和镜头号。存不下时页面上出一条提示，不影响用。
- 想法和画面描述在发给主进程之前先去掉看不见的控制字符（粘贴带进来的垂直制表这类，换行和制表照留），不然主进程整句拒掉、报一句对不上原因的「想法要写 1 到 2000 个字」。
- 写分镜、拼片的时候不出片（`generate` 开头挡住，同 `writePlan` 那边）：写分镜会把镜头整个换掉，付了钱的片段回来时找不到镜头。拼片读片段时边读边加，加起来超过 1 GB 就停在那一段，不把剩下的也读进来。
- 排队、进度不记；已经发出去的那一段记下请求号（没等到结果就失败的也记，服务端可能还在出）。关掉软件或刷新页面再打开，这几段先显示「生成中」，页面拿请求号找主进程接回来（`resumeAiVideo`）：还在出就接着等，已经出完就直接挂回镜头，主进程那边没有这一单就回到「还没生成」。只查不提交，不会再扣一次钱。
- 交出去了却没拿到任务号的那一段（回包丢了、服务端出错、提交到一半点了停止、软件被关掉）：主进程照「提交结果不明确」那句报错（`electron/ai-video-submission.ts`，两边共用），镜头记成「结果不明」（`unconfirmed`）连同请求号一起存下。重开以后直接是「没生成出来」加那句提醒，不去接（没有任务号，接不回来），不会变回「还没生成」让「生成剩下的」再付一次钱（#1489 N2）。要再生成，确认框另外说清「钱可能已经扣了，片段却拿不回来，可能多扣一次」，先勾「我已了解影响」才能点；确认后沿用原来的请求号重新提交，MiniMax 拿它去重。
- 失败了还记着请求号的那一镜（「暂时查不到进度」这类，服务端多半还在出），点「重新生成」先拿这个请求号接回：接得回来就不再提交；主进程那边确实没有这一单，才重新提交、重新计费；主进程说这一单提交结果不明确的，停下照上一条提醒，不换新请求号再付。接回时点了停止、主进程又说没有这一单的，不再提交。
- 排队时连同客户在确认框里点头时的设置一起排，轮到哪一段都照那份出（#1489 R28-4）：页面刚打开、模型表还没读完就点了生成，读完以后记着的模型换成了默认的，排在后面的几段也不会悄悄换模型和时长。那个模型真的用不了了，主进程在扣费之前就拒掉。
- 视频模型从账号所有分组里找（`kind` 是 `video` 的，现在是 Grok 和 MiniMax 两家），默认 `grok-imagine-video-1.5`；每段时长只列这个模型能出的长度。文字模型的菜单和聊天一样按厂商分节。
- 换账号时整页重新挂载（`key={scope}`），上一个账号的请求和进度都作废。

文件：

- `project.ts` — 纯函数：工程的形状、默认值、分镜落成镜头、排序增删、出片段的请求、存取和校验。
- `useVideoStudio.ts` — 页面的状态和对主进程的调用：读模型、写分镜、排队出片段、拼片、存工程。
- `VideoStudioPage.tsx` / `video-studio.css` — 页面本身。

## 主进程那一半

请求都在主进程发，凭据和文件路径不出主进程（`electron/ipc/handlers/ai-video.ts`）：

- `planVideoStudio`：文字型号把一句想法拆成几个镜头，每个镜头一句给视频型号的画面描述和一句字幕（`electron/video-studio-plan.ts`，上限页面也从这里读）。
- `generateAiVideo`：出一段视频，存进全局作品库后回编号、缩略图、宽高和时长；进度经 `onAiVideoProgress` 推回来。只有视频剪辑页用这一条。主进程照画布那套按窗口兜一层（同时最多 20 段在出、每分钟最多 80 次，`canvas-generation-admission.ts`），页面出错或被投毒也不能连发付费视频；每一单等完（出好、失败、停下）提醒主窗口刷新余额，同聊天、生图。
- `resumeAiVideo`：按请求号接回上次没等到的那一段。主进程的任务记录里本来就带着请求号；取回来存进作品库时另记一笔「请求号 → 片段」（`ai-video-task-store.ts` 的 `finish`，只留最近 100 条），所以开机续查已经把片段取回来了，页面晚些打开也对得上。每一单交出去之前先在同一个文件里记一笔「已发出、还没拿到任务号」（`markUnconfirmed`，只留最近 100 条），拿到任务号或服务端明确拒掉时划掉；按请求号接回时碰到它，照「提交结果不明确」报错，不回「没有这一单」。这一笔写不进不拦这次出片，只是少了这层提醒。同一个服务端任务不管是出片段那次、开机续查还是页面接回在等，只查一份、只存一个文件（`ai-video-service.ts` 的 `finishOnce`）。
- `cancelAiVideo`：停下分镜、出视频或接回。已经交给服务端的视频照样生成、照样扣费，下次登录会自己取回来。
- `readAiVideoClip`：读一段视频的全部字节，交给下面的拼片引擎。
- `storeVideoStudioExport`：拼好的成片存进作品库；`openAiVideo` 用电脑默认的播放器打开，`saveAiVideo` 另存。读片段和存成片在主进程按窗口排成一队、一次只搬一段（最多 512 MB），排着的超过 12 个直接拒，连发也撑不爆主进程内存。
- `openDiagnosticFolder('ai-output')`：检查页那条通道，打开 AI 作品文件夹（路径由主进程算，过了 I8 检查才打开）。成片那一行和说到「AI 作品文件夹」的提示旁边都有「打开文件夹」，打不开时按失败说一句。

主窗口的 CSP 没有 `media-src`，页面里放不了视频，看成片靠缩略图加「用播放器打开」。打包版里 `xingmang://` 回的每个文件都带上和 `index.html` 一样的 CSP 响应头（`electron/app-protocol.ts`）：拼片的后台线程只认自己脚本的响应头、不继承页面的 `<meta>`，这样它也连不了外站。

凭据门禁（`scripts/verify-canvas-renderer-boundary.test.cjs`）同样扫本目录和对话页，页面或线程里长出带 Key 的请求会当场红。

## 拼片引擎

`composeInVideoStudioWorker(request, { signal, onProgress })` 在后台线程里拼，页面不卡；`composeVideoStudio` 是同一套，直接在当前线程跑（测试用）。

- **输入**：每段片段的全部字节（MP4 / MOV / WebM）加可选的剪头、剪尾、字幕；成片的画面比例（16:9、9:16、1:1）、清晰度（短边 480 / 720 / 1080）、填充方式（裁边 `cover` / 补黑边 `contain`）和帧率（24 / 25 / 30）。
- **输出**：一个 MP4 的字节、编码、宽高和时长。画面优先 H.264，没有再用 VP9、AV1；声音优先 AAC，Linux 的 Chromium 没有 AAC 编码器，用 Opus。所有片段都没有声音时成片不带音轨。
- **字节会转移**：交给后台线程后 `request` 里的 `ArrayBuffer` 就空了，要重拼就重新读片段。
- **不装 ffmpeg**：解码、编码都用 Electron 自带的 WebCodecs，读写 MP4 用 [mediabunny](https://github.com/Vanilagy/mediabunny)（MPL-2.0，没改它的源码）。
- **上限**：最多 50 段、成片最长 10 分钟、一段最大 512 MB、加起来最大 1 GB；成片整个在内存里组装。

文件：

- `timeline.ts` — 纯计算：成片尺寸、每段从哪儿取、落在成片第几帧。按整帧切，48 kHz 能被每个帧率整除，所以画面和声音拼多少段都不会错开。
- `captions.ts` — 字幕排版：汉字按字断行、英文按词断行，标点不上行首；字号按短边算，竖屏抬到下五分之一；放不下先缩字号再截断。
- `pcm.ts` — 声音拼接：每段先重采样成 48 kHz 立体声再交给编码器，只写这一段自己的时间窗，没有声音的地方是静音。
- `encoding.ts` — 挑这台电脑能用的编码器。
- `compose.ts` — 用 mediabunny 读片段、逐帧画到画布上烧字幕、编码、写 MP4。
- `compose-protocol.ts` — 后台线程两头的消息格式，两边都按白名单读。
- `compose-worker.ts` / `compose-client.ts` — 后台线程本身和页面这一头；取消就直接关掉线程。
- `errors.ts` — 报错上屏一律中文；浏览器抛的英文错误换成一句能照着做的话。

## 验证

```bash
npx vitest run src/renderer-v2/features/video-studio --no-file-parallelism
XINGMANG_E2E_CHROMIUM=/opt/pw-browsers/chromium node --test src/renderer-v2/features/video-studio/browser-check.mjs
```

浏览器测试在页面里现做几段纯色片段（不同尺寸、帧率、有无声音），拼完再解出来量颜色、字幕像素和音量，也核对后台线程、取消和读不了的文件。页面那几条（`page-fixture.html`）用假的主进程桥走完写分镜、生成、拼片、刷新后恢复，生成到一半刷新后接回片段，以及停下分镜和正在生成的片段。不碰网络。

Windows / Mac 上能不能编出 AAC 声音要真机看；编不出也会自动换 Opus，照样出 MP4。
