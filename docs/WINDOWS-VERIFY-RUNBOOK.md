# Windows 真机 / 虚拟机验收 Runbook

> 面向老板的两台机器(租的真机 + 本地虚拟机)。目标是把"装包 → 实测 → 报问题 → 修 → 再出包"这个循环跑顺。
> 第 1~3 节是**测试包**的日常验收;第 4 节是**正式包**(无签名发布)与"检查更新"这条链路,发版前必须过一遍。
> 第 2 节的重点项写于 2026-08 那一轮(画布 503、图生图、账号来源切换),至今仍是有效的回归项。

---

## 0. 两台机器怎么分工

| | 虚拟机 | 租的真机 |
|---|---|---|
| **主要用途** | 安装/卸载/升级、首次启动向导、提权路径 | 日常真实使用、账号类验证 |
| **不可替代之处** | **能回滚到干净状态** | 有真实的 ChatGPT/Claude 登录、真实网络与 Defender |
| **必须做的事** | 每次装包**前**打快照 | 不要频繁重装,当"用户的电脑"来用 |

**虚拟机的铁律:装包前先打快照。** 本软件会写注册表(卸载项、自启动)、写 Program Files、写 `%USERPROFILE%` 下四个 CLI 的配置、可能装 Node.js——装过一次系统就不干净了,"首次安装体验"只有一次机会。测完回滚快照,下一轮又是全新系统。

## 1. 拿包

测试包在 GitHub Actions 的 `test-build` 工作流里,每次推送后我会触发一次。

1. 打开 https://github.com/xufei5620/xingmang-ai-manager/actions
2. 选 `test-build`,找到对应 commit 的那次 run(我每次会把 commit 号发给你)
3. 页面底部 Artifacts 下载 zip,解压得到 `XingMang-AI-Manager-<版本>-Setup.exe`

**关于 SmartScreen 警告**:包**没有签名**,Windows 会弹"未知发布者"蓝色警告。点「更多信息」→「仍要运行」。这不是测试包特有的:产品所有者 2026-09-05 已定,Windows 对外发布固定走无签名模式(`docs/RELEASING.md` 第 1 节),**正式包也会有同一个警告**,不要当成缺陷报上来。

**关于"检查更新"页**:测试包(`npm run build` 出的本地调试包)这一页是灰的,显示「本地开发包不检查更新」——这是故意的,它不连更新服务器。正式的无签名包(`npm run release:build:unsigned`)**保留更新能力**,更新页会多出一行「更新通道:未签名,下载和安装都要你确认」。更新链路要用正式包才能验(见第 4 节)。

## 2. 重点验收项(2026-08 那一轮定下,至今仍有效)

按顺序做,每项记 PASS/FAIL。**发现问题就停下来记录,不要接着往下试**——后面的现象可能是前面那个问题的连锁反应。

### 2.1 安装(虚拟机,干净快照)

- [ ] 安装时能**自选安装目录**(不是被强制装 C 盘)
- [ ] 装完桌面和开始菜单都有快捷方式
- [ ] 首次打开**先进登录界面**,不是直接进主界面
- [ ] 登录界面有「记住密码」勾选框、有同意协议勾选框
- [ ] 注册界面的「用户协议」「隐私政策」能点开
- [ ] 邮箱输入框的示例文字是通用格式（例如 `name@example.com`），不限制邮箱服务商

### 2.2 画布 503 修复(两台都可以,真机更好)

前提:账号已登录。

- [ ] 打开「无限画布」,顶部显示「已连接星芒账号」
- [ ] 新建图像生成节点,**用默认配置**(GPT Image 2 + 低画质 + 1024×1024)输入一句提示词,点运行
- [ ] **成功出图** → PASS
- [ ] 若仍失败 → 记下**完整错误文案**。新版本会把服务端的原因一起显示(比如"当前分组 xxx 下无可用渠道"),这句话是定位的关键,截图给我

> ⚠️ 如果错误里出现"分组"字样,说明 xm 后台没给普通账号开放含图片模型的分组(`生图分组` 或 `openai`)。这是后台配置,不是客户端问题,需要你去 xm 后台开放。

### 2.3 图生图(新功能)

- [ ] 画布模式下加两个「图像生成」节点
- [ ] 把第一个节点的**输出**连到第二个节点的**图像输入口**(左侧第二个圆点,绿色)
- [ ] 第二个节点写改图指令,例如「把猫换成白色布偶猫」
- [ ] 跑通,第二张图是在第一张基础上改的 → PASS

### 2.4 账号来源切换(新功能,**必须在真机上验**)

这一项我在云端只能靠单元测试覆盖,**真机结果是唯一可信证据**。

前提:真机上的 Codex **已经用 ChatGPT 账号登录过**。

- [ ] 打开 Codex 的配置弹窗,保存按钮上方能看到「账号来源:星芒中转」
- [ ] 点「切换为我的 ChatGPT 账号」,确认弹窗里写明"登录不受影响"
- [ ] 确认切换,提示成功
- [ ] **关键验证**:打开 Codex,确认**不需要重新登录**,并且是用你自己的 ChatGPT 订阅在跑 → PASS
- [ ] 回到星芒,配置弹窗里显示「账号来源:ChatGPT 账号」
- [ ] 重新填 Key 保存配置,确认能切回星芒中转
- [ ] 再打开 Codex,确认走的是星芒额度

> 若切换后 Codex 要求重新登录 → **FAIL,立刻告诉我**。这说明 `auth.json` 里的登录凭据被误删了,是这个功能的命门。

## 4. 正式包与"检查更新"(无签名,不需要证书)

前面三节走的都是**测试包**。要验"应用内检测更新 → 下载 → 安装"这条链路,必须用**正式包**,完整流程见 `docs/RELEASING.md`。

**这里不再需要代码签名证书。** 产品所有者 2026-09-05 已定:Windows 对外发布固定使用无签名模式,不需要 `.p12`,也不需要 `XINGMANG_SIGNING_PUBLISHER`。出包入口是:

```powershell
$env:XINGMANG_OUTPUT_DIR = 'release-<版本号>'
npm run release:build:unsigned
```

这一条命令自带发布前置检查、类型检查、全部单测、编译、两个启动冒烟、Electron 加固校验、ASAR 篡改校验,以及 `latest.yml` 的结构 / 大小 / 逐文件 SHA-512 / blockmap 校验(`scripts/run-release-build.cjs` 的步骤表),不需要再手工补跑。无签名模式下只跳过 `latest.yml` 校验里的 Authenticode 签名主体比对这一项,跳过原因会打印在构建日志里。输出目录必须不存在或为空。

你手上仍然要有的只剩一样:**更新服务器的上传权限**。`0.1.2` 及更早使用 `updates.shenfengwl.fun/xingmang-manager/`,`0.1.3+` 使用 `updatesnew.shenfengwl.fun/xingmang-manager/`。

发布顺序有个坑,记牢:**先上传安装包和 `.blockmap`,最后才覆盖 `latest.yml`**。反了的话,用户会在文件还没传完时就被告知有新版本,下载必然失败。

### 4.1 无签名更新的三条路径(M-02,必须过)

无签名包没有安装包签名校验这道闸,所以更新行为被改成**用户确认式**:下面这几条就是这条链路的全部保护(实现在 `electron/updater.ts`)。验的是**升级**不是全新安装——虚拟机上先装旧版本 → 发布新版本 → 回到旧版本里点「检查更新」。

- [ ] **下载要用户确认**:检查到新版本后**不自动下载**,更新页出现下载按钮,点了才下
- [ ] **安装要用户确认**:下载完成后**不自动安装**,要再点一次才装
- [ ] **篡改包被拒**:把下载下来的安装包改几个字节,确认安装被拒绝,并且更新页写明了原因(SHA-512 与更新清单不一致)
- [ ] 更新页有一行「更新通道:未签名,下载和安装都要你确认」
- [ ] 装完版本号变了,原来的配置和登录态还在

> ⚠️ 这几条任何一条不对都**先别发版**,直接告诉我。签名包才是"自动下载 + 校验后自动重启安装";无签名包必须是手动两步。如果它自己下、自己装,说明这个包没有被认成无签名通道(打包时写进 `package.json` 的 `xingmangUnsignedRelease`),那么这次更新是**没有保护**的。

不想真发一版到线上时,可以先用本地更新源演练,见 `docs/RELEASING.md` 第 7 节。

### 4.2 顺带核对

- [ ] 启动时 `runtime.jsonl` 里有一条对应的无签名通道警告
- [ ] `latest.yml` 里每个安装包都写了 `sha512`(缺了客户端会直接拒绝该次更新)
