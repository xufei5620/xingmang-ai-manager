# 开工指令（复制整段发给开发 AI）

> 你是本仓库的 UI 实施代理。目标：用 `ui-spec/`（星芒 UI 体系 v3.1.1）替换现有渲染层的界面，功能范围不变；此后所有界面改动都必须遵守这套体系。

**开始前必读（按顺序）**：`CLAUDE.md` §0 → `ui-spec/HANDOFF.md` → `ui-spec/给验收人的一页纸.md` → `ui-spec/24-old-to-new-map.md` → `ui-spec/11-handoff-phases.md`。视觉与交互以 `ui-spec/prototype/星芒AI管理工具-可交互原型.html` 为准（浏览器打开，顶部检阅条可切平台 / 主题 / 场景 / 异常）。

**硬规则**
1. 新渲染层放 `src/renderer-v2/`，旧 `src/` 只读；主进程改动限 `electron/platform/*` 新文件与明确接入点。
2. 只用 `ui-spec/20-component-api.md` 的组件与 `ui-spec/tokens.css` 的变量；`ui-spec/22-registries.md` 的表做成 `src/renderer-v2/registry/*.ts` 常量，页面只读表。
3. 文案按 `ui-spec/06-copy-guide.md`；图标按 `ui-spec/07-icons-brand.md`（`@lobehub/icons` / `simple-icons` / `lucide-react`），不手画任何品牌标。
4. 版式固定 1280 逻辑宽 + `setZoomFactor` 整体缩放，不写响应式断点（`ui-spec/03`）。
5. 保留旧 e2e 的所有 `data-testid`；新增按 `page-component-action` 命名。
6. 一期一个 PR，用 `.github/pull_request_template.md`，附「原型 vs 实现」截图矩阵（暗 / 亮 × Win / Mac × 默认 / 空 / 失败），完成 `ui-spec/23-governance.md` §3 全部勾选。
7. 规格没覆盖的：先按最相近的组件做，写进 PR「待决策」，不停工。
8. 不改 `sub2api` / `newapi` 源码；自动化测试不打生产接口。

**第一天要交的**
- `docs/prototype-refs/`：原型每页每状态截图。
- `node ui-spec/work/run-final-checks.cjs` 跑通并贴结果。
- Phase 0 PR：`src/renderer-v2/` 骨架、`electron/platform/` 目录、`tokens.css` 接入、三套图标包、16 个组件 + 组件预览页（对照 `ui-spec/prototype/components.html` 逐个核对）、`XINGMANG_RENDERER=v2` 开关。

**之后按 Phase 1 → 4 推进**（`ui-spec/11-handoff-phases.md`）；Linux 为 Phase 5。每个 PR 结束附一句：下一步做什么、需要谁决定什么。
