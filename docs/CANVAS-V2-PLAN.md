# 无限画布 v2:节点式 AI 媒体工作流(规划)

> 起草 2026-08-10 晚,老板令:「从现在开始你开始规划无限画布这一块」。
> 本文是画布 v2 的总规划与决策记录。执行细节随里程碑推进滚动补充;与代码冲突时以代码为准。

## 0. 一句话定位

把画布从「vendored 的第三方生成卡片白板」升级为「第一方的节点式 AI 媒体工作流画布」:**节点 = 一次模型调用,连线 = 媒体数据流转**(文生图 → 图生视频式管线),同时保留「固定输入框 + 模型选择」的简单模式,二者共享同一执行引擎。

**商业本质**:relay 消耗放大器。用户每跑一条管线 = 真实额度消耗(图片/视频 token 单价远高于文本);分发 = 现有桌面客户端与付费客户,不需要独立获客。go/kill 看上线后现有客户的使用率与额度消耗增量,不看外部指标。

## 2. 底座选型:@xyflow/react(React Flow),自建整车

**没有可以安全二开的整车**,这是选型的第一事实:

| 候选 | 排除原因(许可证/范式,均已核实) |
|---|---|
| Jaaz | 社区许可禁止修改源码/二次开发/嵌入商业产品——**一行代码不能碰**,仅作交互对标 |
| ComfyUI | GPL-3.0,嵌入即传染;本地模型 DNA 与低门槛客户群相反。仅在遥远的将来作为「API 隔离的本地引擎」考虑 |
| Flora | 闭源 SaaS,形态最对口的交互参照 |
| tldraw / Excalidraw / Drawnix | 白板范式,无端口与数据流,改造 = 重写 |

**专用节点编辑器库横评**(2026-08-10 多智能体逐项核实,防漏检):

- **Rete.js v2**:唯一可辩护备选(MIT、活跃、官方 React 支持),但需拼装 ~5 个插件 + 强制 styled-components peer 依赖,节点渲染同样落在 React DOM 上——媒体预览能力与 React Flow 持平而集成成本更高;其差异化的 dataflow 执行引擎对本产品无用(执行发生在 relay 服务端)
- **LiteGraph 系**(ComfyUI 自用图库):上游 2024-08 停更;Comfy-Org fork 2025-08 归档并入 GPL-3.0 的 ComfyUI_frontend(Vue 3),npm 包已标 deprecated——**不可作为持续维护的独立依赖**;且 Canvas2D 渲染做 DOM 级媒体预览需覆盖层 hack,适配成本候选中最高
- Baklava.js 仅 Vue 3;Drawflow 休眠 22 个月停在 0.0.x;jsPlumb 社区版停更且只是连线库

**结论:@xyflow/react**(MIT,12.x,持续活跃,Dify/Langflow/n8n 等生产级工作流产品在用)。节点是普通 React 组件(提示词输入/模型下拉/参数区/结果预览/单节点重跑/状态动画),端口用类型系统 + `isValidConnection` 校验(image 输出只能连 image 输入)。

⚠️ **许可红线两条**:①React Flow core 是 MIT,但 **Pro 示例(如 Helper Lines)是付费订阅内容**——需要的对齐参考线等功能自己实现或确认许可后再抄;②Jaaz 的 UI 不做像素级复刻,读源码学架构可以,落手必须自己写。

## 3. 架构:三层,其中两层我们已经拥有

```
┌─ 画布前端(兄弟仓,React Flow)────────────────┐
│  节点组件 / 类型化端口 / 双模式 UI / 模板     │
├─ 执行引擎(同在前端,客户端编排)──────────────┤
│  DAG 拓扑排序 → 逐节点异步任务 → 轮询/重试    │
│  单节点重跑 / 断线恢复 / 费用显示 / 本地落盘   │
├─ 供应商适配层 = xm.solov.cc(已存在!)────────┤
│  new-api 渠道系统:GPT-image/可灵/即梦/Vidu…  │
│  计费记账天然完成(用户额度,个人中心可查)     │
└──────────────────────────────────────────────┘
```

对话里「执行引擎占 80% 工作量」的估计**对我们不成立**:适配层 ≈ 0(relay 渠道配置)、计费 ≈ 0(new-api 记账)、对象存储 ≈ 0(桌面端产物直接落用户磁盘,走现有 saveFile 桥)。真实工作量 = DAG 编排 + 异步任务生命周期 + 节点 UI 打磨。

### relay 端点事实(rc.24 源码逐行核实,2026-08-10)

- 文生图:`POST /v1/images/generations`、`POST /v1/images/edits`(标准路由已存在)
- 视频任务:`POST /v1/video/generations` 提交 → `GET /v1/video/generations/:task_id` 轮询 → `GET /v1/videos/:task_id/content` 取产物(`router/video-router.go`)
- 任务适配器现成:**可灵 / 即梦 / Vidu**(`relay/channel/task/`),即梦另有图像适配器
- **待老板动作**:在 xm 后台为目标模型配置渠道与定价(开工前唯一外部依赖);配置完成后按 T12 标准把实测事实补进 `docs/RECON-new-api.md`

## 4. 数据模型(MVP 刻意最薄)

```ts
Workflow { id, name, nodes: Node[], edges: Edge[], schemaVersion }
Node     { id, type: 'text'|'image'|'video', position, data: { prompt, model, params, result?: AssetRef, status, costQuota? } }
Edge     { id, source, sourceHandle, target, targetHandle }   // handle 携带端口类型,连线时校验
AssetRef { kind: 'image'|'video', localPath?, remoteUrl?, taskId? }
```

- 持久化:JSON 文件,经宿主桥存用户磁盘(两阶段写沿用主应用惯例);媒体产物同目录落盘
- 端口类型 MVP 只有 `text | image | video`;audio/group/子流程后置
- 不做:假设/实验/决策层、协作、云同步、模板市场——等有真实使用数据再加

## 5. 执行引擎要点

1. 画布只描述 DAG;点「运行」→ 拓扑排序 → 就绪节点并发执行(上游产物就位即触发,不做整层 barrier)
2. 每节点一个异步任务:提交 → 轮询(视频任务动辄 1-2 分钟)→ 产物下载落盘 → 状态机 `idle/queued/running/succeeded/failed`
3. 失败重试(带上限)+ **单节点重跑**(下游标脏);应用重启后从持久化的 taskId 恢复轮询(断线恢复)
4. 费用透明:每节点显示本次消耗(new-api 响应/用量接口),画布顶部显示本次运行合计——这类产品用户烧额度快,透明是留存前提
5. 全部请求打 relay 域,复用画布现有 token 注入链(canvas-auth);**测试一律 mock,绝不打生产**(T12 铁律同样适用)

## 6. 桌面宿主改动(本仓,预计很小)

- 隔离窗口、`xingmang-canvas://` 协议、白名单、5 能力桥**全部保留**(I15 姿态不变);v2 是第一方代码,供应链风险较 vendored 反而下降
- 可能新增的桥能力(每项过「画布被投毒后这能力能干什么」审查):
  - `saveGeneratedAsset`(带进度的媒体落盘;现有 saveFile 是否够用待 M1 验证,能复用则不加)
  - 其余暂无——费用/额度查询走画布已有的 relay 直连,不加新 IPC
- `copy-canvas-assets.mjs` 复制链路不变(兄弟仓构建产物 → dist-canvas)

## 7. 里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M0 骨架**(1-2 天) | 兄弟仓起 React Flow 应用:三节点类型 + 类型化端口 + 连线校验 + JSON 持久化;在隔离窗口跑起来 | 画布可搭「文→图→视频」三节点并保存/恢复 |
| **M1 真管线**(2-4 天) | 执行引擎接 relay:文生图直调 + 视频任务轮询 + 产物落盘 + 单节点重跑 + 费用显示 | 一条真实管线端到端出片,消耗记账可见 |
| **M2 双模式**(2-3 天) | 简单模式表单(=单节点)+「展开到画布」;替换现有画布导航入口 | 小白用户不见画布也能出图/出片 |
| **M3 打磨**(滚动) | 模板(如「产品图→带货短视频」)、失败态 UX、断线恢复、对标冲刺(Flora/ComfyUI/Jaaz 各跑同一任务记录摩擦点) | 老板真机验收 + 首批客户灰度 |

M0 前置:①老板在 xm 配好渠道(至少一个图像模型 + 一个视频模型);②定兄弟仓方案(在 `xingmang-canvas` 仓里起 v2 目录,或新仓——建议新目录,复用构建/复制链路)。

## 8. 红线与合规

- Jaaz 零代码引用;ComfyUI 零代码嵌入;React Flow Pro 付费内容不抄
- 现有 vendored infinite-canvas(MIT)在 v2 可用前保持不动,替换时按 MIT 保留版权声明的义务处理归档
- 抓取/内容合规与本产品无关(用户自己生成内容),但生成内容的平台合规(模型侧审核)由 relay 上游模型自带,客户端不再加一层
- 发布红线不变:画布 v2 上线走测试包→灰度,不碰自动更新通道,#28 的灰度前提依旧
